# خطة برمجية للوصول إلى تحقق كامل — VER-01..VER-04

**التاريخ:** 31 أكتوبر 2026 · **الحالة:** منفَّذ في المصدر ومقيس محليًا · **لم يُنشر ولم يُتحقق حيًا مع Meta.**

## 0. قاعدة الصدق: ما معنى «100%»؟

رقم واحد لا يكفي، لأن الاختبارات المحلية لا تُثبت سلوك Meta الحقيقي. لذلك نفصل ثلاث نسب ولا نجمعها في رقم تسويقي:

| المقياس | التعريف الدقيق | الحالة الآن |
| --- | --- | --- |
| **نجاح الاختبارات** | ناجح ÷ (ناجح + فاشل) | **871/871 = 100%** |
| **اكتمال التنفيذ** | منفَّذ ÷ إجمالي الاختبارات (بلا skips) | **871/871 = 100%** (كان 841/858 = 98%) |
| **تغطية الكود** | أسطر/فروع/دوال مُنفَّذة فعليًا | 92.62% / 77.20% / 87.13% |
| **قبول حي (Meta/الإنتاج)** | رحلة حقيقية على رقم حقيقي | **0% — لم تُنفَّذ** |

**الخلاصة:** الوصول إلى 100% في الاختبارات المحلية **تم**، وهو ليس ادعاءً بأن الربط الحي يعمل. القبول الحي يحتاج نشرًا وتفويضًا صريحًا ورقمًا حقيقيًا، ولا يمكن لأي اختبار محلي أن ينوب عنه.

## 1. تشخيص: لماذا لم تكن النسبة 100%؟

لم تكن المشكلة نقص اختبارات، بل **بوابات تبدو خضراء وهي لم تعمل**:

1. **17 اختبارًا متخطّى (`skipped`) في كل تشغيل.** اختبارات قبول العزل الحقيقي (`namespaces`) كانت تتطلب `CELIA_SANDBOX_INTEGRATION=1`، وغير مفعّلة في CI إطلاقًا. محصلة ذلك: أهم اختبارات الأمان لا تُنفَّذ أبدًا، والتقرير أخضر.
2. **بوابة المتصفح كانت تُبلّغ «محجوبة» لا «فاشلة».** غياب Chromium يُنتج «لم نُشغّل» فيقرأها الإنسان كعذر لا كفشل.
3. **اختبار التوافق N/N-1 كان يتخطّى بصمت** لأن نسخة Git ضحلة لا تحتوي commit الأساس.
4. **فحص 320px وحده أخفى عيبًا حقيقيًا** عند 412px (تفصيل في §2).

**المبدأ المستخلص:** أي بوابة يمكن تخطّوها بصمت هي بوابة غير موجودة. الإصلاح ليس «تشغيل المزيد»، بل **منع النجاح الزائف**.

## 2. عيبان حقيقيان اكتشفهما التشغيل الفعلي

### 2.1 انحدار تخطيطي كنت أنا سببه (VER-04)
إضافة رابط «ربط واتساب» إلى شريط `/agent` جعلت عرض الشريط 513px داخل نافذة 412px، فصار عرض الصفحة 529px ودُفع زر «اتصال» إلى ما خارج الشاشة (`x=415` في نافذة عرضها 412) — أي **زر لا يمكن النقر عليه على هاتف حقيقي**.

- لماذا لم يُكتشف؟ `nav { flex-wrap: wrap }` كان محصورًا في `@media (max-width: 360px)`. اختبار 320px يمرّ، وdesktop يمرّ، والمنطقة 361–530px عمياء.
- الإصلاح: الالتفاف في كل العروض + `min-width: 0`. القياس بعد الإصلاح: 529px ← **412px**، والزر داخل الشاشة وقابل للنقر.
- الاختبار الجديد لا يقيس العرض فقط، بل **إصابة النقر** (`elementFromPoint`) عند 361/412/480/530px، لأن «لا يوجد تمرير أفقي» لا تعني «الزر قابل للاستخدام».

### 2.2 مقارنة زمنية غير آمنة (VER-01)
`findWhatsAppVerifyToken` كان يقارن رمز التحقق بـ `===`، وهو تسريب تدريجي عبر التوقيت لمن يستطيع قياس استجابة الـwebhook. استُبدل بـ `constantTimeEqualAsync` — نفس الأداة المستخدمة في مسار التوقيع. أُضيف اختبار يثبت رفض السابقة/اللاحقة/المسافة الزائدة، وأن المصافحة تعمل من البصمة المخزّنة دون رمز بيئي.

## 3. الخطة المنطقية (ما نُفِّذ)

### VER-02 — جعل البوابة غير قابلة للتخطّي
- `scripts/browser-runtime.mjs`: دالة قرار **خالية من I/O** (`chooseBrowser`) ترتّب: مُحدَّد صريح ← Playwright ← النظام ← الحزمة المدمجة. السبب: الترتيب نفسه يجب أن يكون مُختبَرًا، لا اجتهادًا بشريًا وقت الفشل.
- `scripts/run-browser-tests.mjs`: **يخرج بكود 1** إذا لم يوجد متصفح. لا يوجد مسار يخرج 0 دون تشغيل.
- مسار بديل للشبكات المحجوبة: `@sparticuz/chromium` مع فك مكتبات glibc المرفقة (بدونها يفشل التشغيل بـ `libnspr4.so`).
- CI: تفعيل `CELIA_SANDBOX_INTEGRATION=1` على Linux + بوابة ترفض أي `skipped [1-9]` من **نفس** تشغيل التغطية (بلا تكلفة تشغيل ثانٍ)، مع الحفاظ على غلاف `test:coverage:ci` الذي يفرضه عقدا SP-08 والتعليقات.
- 8 اختبارات جديدة تُثبّت الترتيب، ودمج مسار المكتبات، والفشل الصريح، وأن المُحمِّل لا يُستدعى عند وجود متصفح أفضل.

### VER-03 — اختبار مسارات الفشل لا مسار النجاح فقط
التغطية كانت تُظهر أن الأسطر غير المُنفَّذة في `whatsapp-onboarding.js` هي **بالضبط** مسارات الفشل والمصالحة. أُضيفت 4 اختبارات:

| الحالة | المطلوب المُثبَّت |
| --- | --- |
| مهلة أثناء الاشتراك | `subscription_unknown`، صفر صفوف اتصال، **ولا تسجيل** بعد نتيجة مجهولة |
| مهلة أثناء التسجيل | `registration_unknown` + PIN محفوظ قبل الاستدعاء، و**عدم إعادة الإرسال** مطلقًا |
| رفض 4xx | `failed` لا `unknown`، و**عدم تسريب** نص المزوّد |
| إعداد موجود مسبقًا | **صفر كتابة زائدة** للاشتراك/override (idempotence) |

أهم نتيجة: الاختبار الأول الذي كتبته افترض إعادة محاولة عمياء، **فرفضه الكود**. كان الكود صحيحًا واختباري خاطئًا (`AGENTS.md`: لا إعادة تشغيل طفرة خارجية بعد نتيجة مجهولة). صُحّح الاختبار ليُثبّت المنع، ثم يُثبّت أن المصالحة تحدث بالقراءة بعد أن تُبلغ Meta حالة `CONNECTED`. النتيجة: تغطية `whatsapp-onboarding.js` من 92.72% ← **97.78%**.

## 4. ما تبقى فعليًا (لا يُدار بالاختبارات المحلية)

| البند | لماذا لم يُنفَّذ | ما يلزم |
| --- | --- | --- |
| قبول Meta الحي | يحتاج نشرًا + تطبيق Meta مهيّأ + رقمًا حقيقيًا | تفويض صريح بالنشر، ثم رحلة حقيقية وتوثيق النتيجة |
| MySQL الحقيقي | لا خادم MySQL في هذه البيئة | مهمة CI `mysql` الموجودة (8.4 + استعادة نسخة) |
| تغطية الفروع 77% | مسارات دفاعية متبقية | رفع تدريجي بلا اختبار وهمي لرفع الرقم |
| بريد تحقق/استعادة كلمة مرور | لا مزوّد بريد مُعدّ | قرار مزوّد ثم تنفيذ |
| رد آلي للمستخدم العادي | مطفأ عمدًا | قرار منتج مستقل |

## 5. أوامر التحقق القابلة للتكرار

```sh
npm ci
npm run check
npm run release:check
CELIA_SANDBOX_INTEGRATION=1 npm run test:coverage:ci   # 871/871، صفر تخطّي
npm run test:browser                                  # 38/38 أو فشل صريح
npm run build:pages
npm run check:secrets && npm run check:continuity
npm audit --omit=dev --audit-level=moderate
```

**قاعدة مكتوبة:** أي تقرير يقول «ناجح» مع `skipped > 0` هو تقرير ناقص، وأي بوابة متصفح لا تجد متصفحًا يجب أن تُخرج فشلًا لا عذرًا.
