# استيراد Google Drive الانتقائي — 29 أكتوبر 2026

**النطاق:** قراءة Drive المتاح عبر الموصل، ثم إدخال خلاصات مفيدة إلى شبكة المعرفة المحلية.
**الوضع:** قراءة فقط على Drive؛ لا حذف أو نقل أو مشاركة أو رفع أو تعديل لأي ملف هناك.
**النتيجة:** أُضيفت خلاصتان موثقتا المصدر إلى `data/kb/drive_registry.csv`، لا نسخة خام من Drive ولا مزامنة مستمرة.

## 1. ما فُحص وحدود الاكتمال

- `list_drives` أعاد **صفر Shared Drives**؛ فُحص My Drive المتاح للحساب.
- استعلام العناصر المعدلة بعد `2026-10-01T00:00:00Z` أعاد **16 عنصرًا بلا صفحة تالية**. هذا استعلام تاريخ تعديل، وليس إثباتًا أن كل محتوى الحساب قُرئ.
- فُحصت مجلدات وملفات CeliaOS وCeliaOS_2026 وcelia_computer_agent وAI_Agent_Router، وتقارير CELIA_FORGE المختارة. قوائم root والبحث العام كانت مقطوعة في بعض الاستجابات؛ لذلك لا يُدّعى مسح كل حساب Drive.
- تقرير `CELIA_DRIVE_AUDIT.md` يذكر **5,858 مجلدًا و38,447 ملفًا** في 9 أغسطس 2026. هذه أرقام تاريخية من تقرير قديم، وليست جردًا حيًا جديدًا.
- لا يعني ظهور ملف في قائمة أو تقرير أن الكود داخله صالح أو منفذ؛ قورنت العينات بملفات المستودع الحالية قبل تصنيفها.

## 2. ما أُدخل فعلًا إلى النظام

| السجل | المصدر | ما أُخذ منه | حدوده |
|---|---|---|---|
| `kb-drive-agent-roadmap` | [خارطة طريق Celia Agent](https://drive.google.com/file/d/1-qkDecKnfatdiB0_rZelgeokp7y2EZuO/view) | مراحل M0–M8، وعقود Task/Action/Observation/ToolResult/VerificationResult، ودورة Plan→Execute→Observe→Verify | مرجع تخطيطي قديم؛ لا يثبت وجود implementation، ولم يُنسخ كوده |
| `kb-drive-celiaos-gap-plan` | [خطة سد فجوات CeliaOS](https://docs.google.com/document/d/1HEv5hkdaYfGu8akZkR3fFcyis3sJrstF2jwiikQE0PA/edit) | موضوعات webhook/SSRF/OAuth/readiness وقرارات المالك، مع تمييز الحالة التاريخية | لا يثبت إصلاحًا حيًا أو اتصال Google/WhatsApp أو جاهزية نشر |

أُضيف المصدر `src-google-drive-curated` إلى `sources_registry.csv` و`descriptors.json`، وأعيد بناء `manifest.json` ببصمات SHA-256. الاستيراد يمر بعقود CSV الحالية: ترخيص `internal-owner`، ثقة `T1`، كشف الأسرار، وفحص الحواف. الكتابة في فهرس SQLite تتم فقط بأمر استيراد صريح؛ لا يوجد موصل Drive حي داخل التطبيق ولا جدولة مزامنة.

**نوع الفهرسة:** FTS5 معجمي وروابط Evidence فقط. لا embeddings، ولا فهرسة دلالية لقاعدة الكود، ولا تغيير في مخطط MySQL أو عقود الوكيل.

## 4. أثر ذلك على خطة phone-google

1. **الوكيل:** تتقاطع الخارطة مع ما هو موجود في `src/agent/runtime.js` وأدلة `plan_created`/`tool_selected`/`tool_executed`/`verification_result`. هذا توثيق متقاطع، لا دليل Gemini حي.
2. **الفجوة التالية:** تبقى AGENT-003 (Sandbox) قبل أدوات الملفات/Shell/Git، ثم إعادة تخطيط محدودة للفشل الداخلي، ثم توسيع الأدوات داخل عزل وموافقات. لم تُستورد أدوات تنفيذ جديدة.
3. **التوجيه والذاكرة:** لا يُعد `selector.py` محرك Model Routing ولا `memory_fabric.py` نظام ذاكرة دلاليًا. لا تُفعّل هذه القدرات بمجرد وجودها في Drive.
4. **التكاملات:** بقيت بنود Google OAuth وWhatsApp وMySQL وBranch Protection قرارات/تحققات مالك أو بيئة، لا عمليات نفذها هذا الاستيراد.
5. **البحث:** أصبحت الخلاصتان قابلتين للاسترجاع عبر `kb.search` بعد تطبيق الاستيراد المحلي، مع رابط المصدر ودرجة الثقة؛ لا تُرفع الثقة تلقائيًا بسبب وجود المستند.

## 5. ما لم يحدث

- لا تشغيل `live-gemini` ولا اختبار جودة نموذج حي؛ AI-001 يبقى غير مغلق كتشغيل حي.
- لا إرسال WhatsApp ولا إنشاء Calendar ولا OAuth ولا نشر ولا ترحيل MySQL.
- لا استيراد أعمى لكل Drive، ولا KB تلقائي عند الإقلاع، ولا تعديل على ملفات Drive.
- لا ادعاء قبول Chromium/MySQL، ولا جاهزية إنتاجية، ولا تفعيل Computer Use أو Model Routing.

```sh
npm run kb:manifest
npm run kb -- verify
npm run kb -- import --apply
npm run kb -- search "خارطة الوكيل"
npm run check:secrets
npm run check:continuity
```

- `node scripts/kb.mjs import --apply` على فهرس SQLite محلي جديد → **81 إضافة، 0 مرفوض**.
- إعادة الأمر نفسه → **81 بلا تغيير، 0 إضافات، 0 مرفوض**؛ لم يتكرر المحتوى.
- `kb.search "خارطة الوكيل"` و`kb.search "خطة الفجوات"` أظهرا السجلين الجديدين مع `sourceId=src-google-drive-curated` و`trust=T1` وروابط المصدر.
