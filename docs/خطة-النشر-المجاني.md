# خطة النشر المجاني — مساعد الهاتف + Google (سيليا)

> الهدف: نشر المنظومة على الإنترنت بميزانية **صفر دولار**، برابط حقيقي و HTTPS، دون رفع أي سر إلى Git.
> هذا الملف يوثّق الخطة **وحالة التنفيذ الفعلية** كما جرى داخل الجلسة.

---

## 1. المشروع في سطرين

المستودع يحتوي خادم Node.js (Express) يقدّم:

- واجهة عربية كاملة (`public/index.html`, `live.html`, `skills.html`).
- خادم MCP بصيغة JSON-RPC 2.0 على `POST /mcp` مع ١٢ أداة (Gmail, Drive, Calendar, Contacts, WhatsApp, AI, Skills).
- طبقة sandbox عامة على `POST /ui/workspace/rpc` و`POST /ui/workspace/crypto-lab` و`GET /health` تعمل على ذاكرة مؤقتة **بلا أي مفاتيح**.

نقطة التشغيل الكاملة للواجهة هي `node src/celia-mcp.js` (وليست `src/server.js` التي تخدم واجهات API فقط وتحتاج MySQL).

## 3. ما نُفِّذ فعليًا في هذه الجلسة

### أ) تشغيل حيّ كامل (Zero-config) ✅

تم تشغيل الخادم الحقيقي على `0.0.0.0:3010` بمخزن الذاكرة:

```bash
CELIA_MCP_DISABLE_MYSQL=true \
CELIA_MCP_API_TOKEN=$(openssl rand -hex 32) \
CELIA_MCP_HOST=0.0.0.0 CELIA_MCP_PORT=3010 NODE_ENV=production \
node src/celia-mcp.js
```

نتائج التحقق الحيّة (curl على الخادم نفسه):

| الفحص | النتيجة |
|---|---|
| `GET /` و`/live.html` و`/skills.html` | 200 · `text/html` |
| `GET /live.js` و`/skills.js` و`/app.js` | 200 · `application/javascript` |
| `GET /health` | 200 · `storage: memory` · `toolsCount: 12` |
| `POST /ui/workspace/rpc` → `tools/list` | ١٢ أداة |
| `POST /ui/workspace/crypto-lab` (audit) | `decryptedMatchesOriginal: true`, `whatsappHmacVerified: true`, `tamperRejected: true` |
| موافقة + رسالة واردة محاكاة | `hmacVerified: true`, `customerWindow24hOpen: true`, `autoReplyAllowed: true` مع رد عربي |
| `GET /api/skills/find?q=whatsapp` | ٥ مهارات مطابقة من ١٢ |
| `POST /mcp` بوضع المالك (Bearer) | `system_live_view` يعمل |

هذا الخادم هو الرابط الحي الذي يظهر لك في المعاينة (Live Preview). أي زائر يصل إليه عبر HTTPS بلا أي مصادقة للواجهة العامة.

### ب) إصلاح توافق CSP (كان يعطّل صفحتين) ✅

سياسة `script-src 'self'` في `src/celia-mcp.js` كانت تحجب `<script>` المضمّن في `live.html` و`skills.html` و`onclick=` في `skills.html`، فتصبح الصفحتان بلا بيانات. تم:

- نقل السكربتات إلى `public/live.js` و`public/skills.js` وإضافتهما كمسارات في `src/celia-ui.js`.
- استبدال كل `onclick=` بأحداث `data-*` + `addEventListener`.
- النتيجة: صفر سكربت مضمّن في الصفحات الثلاث، والصفحتان تعملان الآن تحت نفس CSP.

### ج) نسخة ثابتة للنشر على GitHub Pages ✅ (جاهزة، غير مفعّلة)

- `scripts/build-pages.mjs` يبني `dist/` ويستخرج `MCP_TOOLS` و`SERVER_INFO` **نصًّا من `src/celia-mcp.js`** (مصدر حقيقة واحد)، ويحقن `<script src="./celia-static-shim.js">` قبل `</head>`، ويحوّل `./live` و`./skills` إلى `.html`، ويضيف `.nojekyll` و`404.html` و`robots.txt`.
- `scripts/static/celia-static-shim.template.js` طبقة تعترض `fetch` لنفس الأصل وتخدم:
  - `GET /health`, `/healthz`, `/api/live`, `/api/skills`
  - `POST /ui/workspace/rpc` و`/mcp`: `initialize`, `ping`, `tools/list`, `tools/call` (١٢ أداة), `resources/*`, `prompts/*`
  - `POST /ui/workspace/crypto-lab`: **AES-256-GCM + HMAC-SHA256 + SHA-256 حقيقية عبر Web Crypto** (فك تشفير مطابق ورفض تلاعب فعلي)
  - بيانات Google/WhatsApp موسومة `demo: true` / `staticPreview: true`، وشارة معاينة أسفل الشاشة.
- `test/static-shim.test.js`: ١١ اختبارًا (البناء، صفحة الهبوط، سلامة الروابط، المصافحة، حارس السياسة، دورة موافقة واتساب ونافذة ٢٤ ساعة، التشفير، Find Skills، Live View، بيانات Google، نقاط REST).
- `.github/workflows/pages.yml`: تثبيت → `npm run check` → اختبارات الطبقة الثابتة → بناء → فحص تسريب أسرار في `dist` → `configure-pages` → `upload-pages-artifact` → `deploy-pages`.

### د) بديل دائم للخادم الكامل ✅ (جاهز للتفعيل)

- `Dockerfile.mcp`: صورة إنتاج للخادم الكامل (ذاكرة، مستخدم غير جذري، منفذ 3010).
- `render.yaml`: Blueprint بنقرة واحدة على Render Free (`generateValue` لرمز MCP، `healthCheckPath: /health`).
- نفس الصورة تعمل على Koyeb وFly.io وHugging Face Spaces.

## 4. لماذا لم يُفعَّل GitHub Pages تلقائيًا؟ (سبب تقني موثّق)

1. حالة المستودع قبل المحاولة: `has_pages: false` (لم يُفعَّل موقع Pages أبدًا).
2. المحاولة عبر API بالتوكن المتاح:
   ```
   POST /repos/celiaelazamey-arch/phone-google/pages {"build_type":"workflow"}
   → 403 Resource not accessible by integration
   ```
3. والمحاولة نفسها من داخل GitHub Actions عبر `GITHUB_TOKEN` (`pages: write` + `enablement: true`):
   ```
   Create Pages site failed: Resource not accessible by integration
   ```
4. السبب: إنشاء موقع Pages لأول مرة يتطلب صلاحية إدارية (owner/admin) لا تُمنح لتوكنات التطبيقات ولا لـ `GITHUB_TOKEN`. لذلك توقّف سير العمل عند خطوة `configure-pages` فقط، ونجحت قبله كل خطوات البناء والاختبار والفحص.

**الحل: نقرة واحدة من مالك المستودع** — Settings → Pages → Build and deployment → Source: **GitHub Actions**، ثم تشغيل `Deploy (GitHub Pages)` من تبويب Actions (أو أي دفع إلى `main`). يصبح الرابط:

```
https://celiaelazamey-arch.github.io/phone-google/
```

سير العمل مُصمَّم ليظهر تحذيرًا واضحًا في `Summary` بدل الفشل الصامت، ولينشر تلقائيًا فور التفعيل.

## 5. الأسرار المطلوبة للنسخة الكاملة فقط (ليست للواجهة الثابتة)

| المتغير | الغرض | كيف تحصل عليه مجانًا |
|---|---|---|
| `APP_API_TOKEN` | حماية مسارات `/api/*` في `src/server.js` | `openssl rand -hex 32` |
| `TOKEN_ENCRYPTION_KEY` | تشفير رموز Google | `openssl rand -base64 32` |
| `CELIA_MCP_API_TOKEN` | وضع المالك على `POST /mcp` | `openssl rand -hex 32` (أو `generateValue` في Render) |
| `MYSQL_*` | قاعدة البيانات | TiDB Cloud / Aiven / MySQL محلي |
| `GOOGLE_CLIENT_ID/SECRET` | OAuth | Google Cloud Console (مجاني) |
| `GEMINI_API_KEY` | الردود الذكية | Google AI Studio (طبقة مجانية) |
| `WHATSAPP_*` | Cloud API | Meta for Developers (مجاني) |

تُوضع في **GitHub → Settings → Secrets and variables → Actions** أو في `.env` محلي متجاهَل، ولا تُكتب في أي ملف يُرفع. سير عمل Pages **لا يحتاج أي سر** (وفيه خطوة ترفض البناء إن ظهرت قيمة تشبه سرًّا داخل `dist`).

## 6. النطاق المخصص (اختياري، مجاني)

- لا يمكن وضع `CNAME` على `*.github.io`؛ استخدم نطاقًا تملكه.
- شهادات HTTPS على Pages مجانية وتلقائية (Let's Encrypt) بعد ربط الـ DNS.
- أضف `TXT` للتحقق ثم `CNAME` إلى `<user>.github.io`.

## 7. WhatsApp Webhook

نسخة Pages **ثابتة ولا تستقبل POST**، لذا لا يمكن تسجيل `/webhooks/whatsapp` عليها. الخيارات:

1. سجّل الـ Webhook على خادم Node دائم (`render.yaml` أو Docker) عبر `https://<host>/webhooks/whatsapp`.
2. أثناء الاختبار: نفق مؤقت `cloudflared tunnel --url http://localhost:3010`.

## 8. القيود المعروفة (معلنة في الواجهة)

- النسخة الثابتة: البيانات في ذاكرة التبويب وتضيع عند التحديث (`storage: memory`)، وGoogle/WhatsApp `demo: true`، ولا إرسال رسائل حقيقي.
- الخادم الحي داخل الجلسة: يعمل ما دامت الجلسة/العملية قائمة؛ البيانات في الذاكرة.
- محرك الردود الافتراضي في النسختين هو `celia-local-policy-engine` (مجاني بلا مفتاح)؛ Gemini يعمل عند توفير المفتاح (خادم أو لصقه في تبويب «النماذج المجانية» داخل متصفحك).

## 9. الترقية لاحقًا (نفس الملفات، بلا إعادة كتابة)

1. Render Blueprint (`render.yaml`) أو Cloudflare/ Koyeb لتشغيل `src/server.js` أو `src/celia-mcp.js` بشكل دائم.
2. ضبط `APP_BASE_URL` و`GOOGLE_REDIRECT_URI` على النطاق الجديد.
3. MySQL مُدار (TiDB Cloud free) + `npm run db:init`.
4. إضافة الأسرار في منصة الاستضافة، ثم تسجيل Webhook واتساب على `/webhooks/whatsapp`.

## 10. ملاحظة عن بدائل الـ CDN

جُرِّبت بدائل مجانية بدون حساب لخدمة ملفات HTML من المستودع:

- `cdn.jsdelivr.net/gh/...` و`cdn.statically.io/gh/...` تخدم ملفات `.html` بنوع `text/plain` (حماية من التصيّد) ⇒ تُعرض كشفرة لا كصفحة.
- `raw.githack.com` يخدم `text/html` لكن بعد صفحة تحذير وسيطة لكل زائر جديد.

لذلك اعتُمد GitHub Pages كمسار دائم، وRender للخادم الكامل، ولم يُعتمد أي وسيط خارجي.
