# خطة النشر المجاني — مساعد الهاتف + Google (سيليا)

> الهدف: نشر المنظومة على الإنترنت بميزانية **صفر دولار**، برابط حقيقي و HTTPS، مع الحفاظ على الخصوصية وعدم رفع أي سر إلى Git.
> تنفيذ الخطة يتم مباشرة بعد كتابتها (سجل التنفيذ في نهاية الملف).

---

## 1. المشروع في سطرين

المستودع يحتوي على خادم Node.js (Express + MySQL) يقدّم:

- واجهة عربية كاملة (`public/index.html`) لمساحة الوكيل الذكي.
- خادم MCP بصيغة JSON-RPC 2.0 على `POST /mcp` مع ١٢ أداة (Gmail, Drive, Calendar, Contacts, WhatsApp, AI, Skills).
- طبقة "sandbox" عامة على `POST /ui/workspace/rpc` و`POST /ui/workspace/crypto-lab` و`GET /health` تعمل على ذاكرة مؤقتة دون أي مفاتيح.

الواجهة لا تحتاج إلا لنقطتَي `GET /health` و`POST /ui/workspace/rpc` لتعمل بالكامل، وهذا هو المفتاح في خطة النشر المجاني.

## 2. مقارنة خيارات الاستضافة المجانية

| الخيار | التكلفة | يشغّل Node؟ | يحتاج بطاقة/حساب خارجي؟ | مناسب لـ |
|---|---|---|---|---|
| **GitHub Pages** (مسار ثابت + طبقة محاكاة داخل المتصفح) | ٠ | لا (ملفات ثابتة) | لا — نفس حساب GitHub | نشر الواجهة وكل الأدوات للعرض والتجربة فورًا |
| Cloudflare Pages (Functions) | ٠ | نعم (Workers) | نعم (حساب Cloudflare) | تشغيل MCP حقيقي بلا خادم دائم |
| Render / Koyeb / Fly.io (Free tier) | ٠ (مع سُبات) | نعم | نعم | تشغيل `src/server.js` مع MySQL مُدار خارجي |
| Hugging Face Spaces (Docker) | ٠ | نعم | نعم | تجربة الخادم الكامل مع تخزين مؤقت |
| VPS مجاني (Oracle Cloud Always Free) | ٠ | نعم | نعم + بطاقة للتحقق | الإنتاج الحقيقي مع MySQL محلي |

**القرار المنفَّذ الآن:** GitHub Pages لأنها الوحيدة التي لا تحتاج أي حساب أو مفتاح جديد، وتحقّق شرط "الصفر" بلا بطاقة ولا تسجيل، وتعمل بنفس بيانات الدخول الموجودة للمستودع.

## 3. المعمارية المنشورة (GitHub Pages)

```
المتصفح
  └─ index.html / live.html / skills.html  (تصميم ثابت، عرض ⭐)
       └─ celia-static-shim.js  ← مُولَّد وقت البناء من مصدر المشروع
            ├─ يعترض fetch('./health')          → ملخص حالة حقيقي مُشتق من أدوات MCP
            ├─ يعترض fetch('./ui/workspace/rpc') → JSON-RPC كامل (initialize, tools/list,
            │                                       tools/call, resources/*, prompts/list)
            ├─ يعترض fetch('./ui/workspace/crypto-lab') → AES-256-GCM + HMAC-SHA256
            │                                             حقيقي عبر Web Crypto API
            └─ يوسم كل استجابة برأس  x-celia-static: 1
```

- **مصدر الحقيقة** يبقى في `src/celia-mcp.js`: سكربت البناء يستخرج `MCP_TOOLS` و`SERVER_INFO` نصًّا من المصدر ويحقنهما في الطبقة الثابتة، فلا تنشأ نسخة ثانية للتعريفات تتباعد مع الوقت.
- **التشفير حقيقي** وليس تمثيليًا: `crypto.subtle` في المتصفح ينفّذ AES-256-GCM (فك تشفير مطابق + رفض التلاعب) وHMAC-SHA256 وSHA-256، بنفس الأشكال التي تُرجعها `src/celia-ui.js`.
- **بيانات Google وواتساب** في هذا الوضع *عرض توضيحي* وموسومة صراحةً `demo: true` / `staticPreview: true`، ولا تُرسل أي رسالة واتساب حقيقية.
- الأسرار (`APP_API_TOKEN`, `TOKEN_ENCRYPTION_KEY`, `GOOGLE_CLIENT_SECRET`, `GEMINI_API_KEY`, WhatsApp tokens) **لا تدخل نسخة Pages إطلاقًا**؛ ولا يحتاج البناء إليها.

## 4. خطوات التنفيذ (كما نُفِّذت فعليًا)

1. **لوحة الحالة**: تم التأكد أن المستودع عام (`public`) وأن صلاحية الحساب `admin` على المستودع.
2. **سكربت البناء** `scripts/build-pages.mjs`:
   - يقرأ `public/` ويكتب `dist/`.
   - يستخرج `MCP_TOOLS` و`SERVER_INFO` من `src/celia-mcp.js`.
   - يولّد `dist/celia-static-shim.js` من القالب `scripts/static/celia-static-shim.template.js`.
   - يحقن `<script src="./celia-static-shim.js">` قبل `</head>` في كل صفحة.
   - يحوّل الروابط `./live` و`./skills` إلى `./live.html` و`./skills.html` (لأن Pages لا يحل المسارات بلا امتداد).
   - ينسخ `index.html` إلى `404.html`، ويضيف `.nojekyll` و`robots.txt`.
3. **اختبارات الطبقة الثابتة** `test/static-shim.test.js`: تنفيذ البناء ثم استدعاء كل الأدوات محليًا في Node (Node 22 يوفّر `fetch` و`Response` و`crypto.subtle`).
4. **سير عمل النشر** `.github/workflows/pages.yml`:
   - `on: push (main) + workflow_dispatch`، الصلاحيات: `contents: read`, `pages: write`, `id-token: write`.
   - `build` → `npm ci` + `npm run check` + `node scripts/build-pages.mjs` + `upload-pages-artifact`.
   - `deploy` → `actions/deploy-pages` في بيئة `github-pages`.
5. **تفعيل Pages من الـ API**: `POST /repos/{owner}/{repo}/pages` بـ `build_type: workflow`.
6. **الدمج إلى `main`** عبر Pull Request حتى يعمل النشر من الفرع الافتراضي.
7. **التحقق**: قراءة حالة النشر من الـ API + رابط التشغيل داخل ملخص سير العمل + فحص الصفحات المنشورة.

## 5. الأسرار المطلوبة فقط للنسخة الكاملة (وليست للواجهة)

| المتغير | الغرض | كيف تحصل عليه مجانًا |
|---|---|---|
| `APP_API_TOKEN` | حماية مسارات `/api/*` | `openssl rand -hex 32` |
| `TOKEN_ENCRYPTION_KEY` | تشفير رموز Google | `openssl rand -base64 32` |
| `CELIA_MCP_API_TOKEN` | وضع المالك على `POST /mcp` | `openssl rand -hex 32` |
| `MYSQL_*` | قاعدة البيانات | TiDB Cloud / Aiven / MySQL محلي |
| `GOOGLE_CLIENT_ID/SECRET` | OAuth | Google Cloud Console (مجاني) |
| `GEMINI_API_KEY` | الردود الذكية | Google AI Studio (طبقة مجانية) |
| `WHATSAPP_*` | Cloud API | Meta for Developers (مجاني) |

تُوضع في **GitHub → Settings → Secrets and variables → Actions** أو في `.env` محلي متجاهَل، ولا تُكتب في أي ملف يُرفع.

## 6. النطاق المخصص (اختياري، مجاني)

- لا يمكن وضع `CNAME` على `*.github.io`؛ استخدم نطاقًا تملكه.
- شهادات HTTPS على Pages مجانية وتلقائية (Let's Encrypt) بعد ربط الـ DNS.
- للتحقق من الملكية أضف سجل `TXT` ثم `CNAME` إلى `<user>.github.io`.

## 7. WhatsApp Webhook على نسخة Pages

Pages **ثابتة ولا تستقبل POST**، لذا لا يمكن تسجيل `/webhooks/whatsapp` عليها. خيارَان:

1. أبقِ المحاكي (`crypto-lab`) للعرض، وسجّل الـ Webhook على خادم Node (Render/Koyeb/Cloudflare) لاحقًا.
2. استخدم نفقًا مؤقتًا (`cloudflared tunnel --url http://localhost:3010`) أثناء الاختبار مع Meta.

## 8. القيود المعروفة (موسومة في الواجهة)

- البيانات في الطبقة الثابتة تعيش في ذاكرة التبويب فقط وتضيع عند التحديث (`storage: memory`).
- Google/WhatsApp تعرض بيانات نموذجية `demo: true`؛ لا OAuth حقيقي ولا إرسال.
- لا محرك LLM سحابي في هذه النسخة؛ الردود تُولَّد بمحرك السياسة العربي المدمج (`celia-local-policy-engine`) — مجاني تمامًا بلا مفتاح.
- زر "وضع المالك" يعمل في المتصفح فقط لأغراض العرض؛ المصادقة الحقيقية تبقى على الخادم.

## 9. الترقية لاحقًا إلى خدمة كاملة (نفس الملفات، بلا إعادة كتابة)

1. Cloudflare Pages + Functions أو Render (Docker) لتشغيل `src/server.js`.
2. ضبط `APP_BASE_URL` و`GOOGLE_REDIRECT_URI` على النطاق الجديد.
3. MySQL مُدار (TiDB Cloud free) + `npm run db:init`.
4. إضافة الأسرار في منصة الاستضافة، ثم تسجيل Webhook واتساب على `/webhooks/whatsapp`.
