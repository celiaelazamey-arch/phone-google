# نشر سيليا مجانًا — خادم كامل، لا واجهة ثابتة فقط

**حزمة التنفيذ:** 0.2.1، 27 أكتوبر 2026. **حالة النشر العام:** غير منفذ حتى إنشاء حسابات الاستضافة وربط قاعدة البيانات. عمل الكود أو نجاح CI لا يثبت نشر خدمة في حسابك.

## الاختيار والحدود

- **Render Free:** خدمة Node/Docker واحدة، وHTTPS ورابط فرعي يعيّنه المزوّد من نوع `<service>.onrender.com`. المصدر الرسمي يعرض المسار الأساسي بلا بطاقة، لكنه محدود وينام بعد الخمول؛ ليس قدرة غير محدودة أو SLA. [1](https://render.com/articles/platforms-with-a-real-free-tier-for-developers-in-2026)
- **Aiven Free MySQL:** قاعدة MySQL مُدارة خارج القرص المؤقت، بخطة مجانية لا تنتهي بعد 30 يومًا وموارد محدودة ونسخ لدى المزوّد. ليست HA، وقد تُوقف بعد خمول طويل. [2](https://aiven.io/docs/products/mysql/concepts/mysql-free-tier)
- **قد يُطلب تحقق أمني من بعض حسابات Render.** إذا طُلبت بطاقة فتوقف، ولا تضف وسيلة دفع أو تختَر خطة مدفوعة. لا نضمن إلغاء متطلبات مكافحة الاحتيال ولا نتجاوزها. [3](https://community.render.com/t/free-tier-payment-error/36531)
- الرابط المجاني **نطاق فرعي**، لا ملكية نطاق مدفوع. لا شراء DNS أو اشتراكات أو بطاقات ضمن التنفيذ.
- لم نختر Hugging Face Docker لكون إنشاء compute Spaces أصبح يتطلب خطة مدفوعة وفق الوثائق الحالية؛ لا نعتمد شروحات مجانية قديمة. [4](https://huggingface.co/docs/hub/en/spaces-overview)

هذه حدود راجعناها بتاريخ الوثيقة؛ راجع شروط المزوّد عند الإنشاء.

## ما تغيّر فعليًا في التطبيق

- `CELIA_ENABLE_INTEGRATIONS=true` يضيف **المسارات الموجودة نفسها** لـGoogle OAuth/REST وWhatsApp Webhook/REST إلى منفذ MCP والواجهة. لا يحتاج خادمين مجانيين منفصلين.
- الوضع القديم يبقى الافتراضي عند غياب الخيار؛ `npm start` لخادم REST المستقل باقٍ أيضًا.
- HMAC يعمل على bytes الأصلية قبل JSON؛ موافقات WhatsApp/AI ونافذة الخدمة وBearer وعزل الأعطال باقية.
- MySQL يستخدم TLS موثّقًا مع `verifyIdentity=true` للتحقق من اسم المضيف صراحةً، مع CA مخصصة عند الحاجة. لا `rejectUnauthorized:false`.
- `CELIA_DB_INITIALIZE=empty-only` تهيئة اختيارية لأول قاعدة **فارغة ومخصصة** فقط، باستخدام schema1 الأصلي. تفحص قفلًا وتركيب الجداول، وترفض إصلاح/ترحيل قاعدة جزئية أو غير متوافقة. لا DROP أو ALTER أو تغيير بيانات موجودة.
- `/deploy` و`/api/deployment` يعرضان فحصًا فعليًا منقحًا؛ لا يستدعيان مزوّدًا ولا ينشران ولا ينفذان ترحيلًا. حالة «غير متحقق» ليست نجاحًا.
- في Pages تعرض الصفحة أنها تجربة متصفح، دون خادم أو تخزين دائم مزعوم.

لا توجد إضافة ذاكرة عامة دائمة لمحادثات الاستوديو في هذه الحزمة؛ ما زالت DATA-002 مهمة مستقلة. قاعدة MySQL الحالية تحفظ أنواع البيانات الموجودة بالمشروع، ومنها OAuth ورسائل/موافقات WhatsApp.

## لماذا لا أُنشئت الاستضافة آليًا داخل هذه الجلسة؟

المستخدم أكد أن الموجود GitHub فقط، ولا توجد بيانات اعتماد استضافة مفوضة في البيئة. موصل Render/Aiven ليس متاحًا للجلسة؛ لا ننشئ هوية أو نتجاوز تسجيل الدخول. محاولة إنشاء Pages عبر الصلاحية الحالية أعادت `403 Resource not accessible by integration`؛ صلاحية إدارة مستودع لا تمنح كل صلاحيات التطبيقات تلقائيًا.

الأسرار لا تُطلب في الدردشة أو Git؛ أدخلها لدى المزوّد فقط. لا تُسمّى المعاينة المؤقتة رابط إنتاج دائمًا.

## الخطوة 1 — أنشئ قاعدة مخصصة على Aiven

1. افتح https://aiven.io/free-mysql-database وسجّل الدخول بنفسك.
2. اختر **Free**، وليس trial أو Developer مدفوعًا، وأنشئ MySQL.
3. أنشئ قاعدة **جديدة فارغة** مخصصة لسيليا أو استخدم قاعدة defaultdb فقط بعد التأكد أنها فارغة.
4. احتفظ بقيم Host / Port / Database / User / Password في مخزن الأسرار، ونزّل شهادة CA. لا تنسخ بيانات العملاء أو ملف الاتصال إلى Git.
5. حوّل CA إلى base64 محليًا؛ هذه شهادة عامة وليست مفتاحًا خاصًا:

```sh
openssl base64 -A -in ca.pem
```

عند طلب معلومات جدار ناري، اتبع نطاقات الخروج الفعلية لخدمة Render بعد إنشائها؛ لا ننشر منفذ MySQL محليًا للعالم ولا نعطل التحقق من TLS.

## الخطوة 2 — افتح ملف Render الكامل

[إنشاء خدمة من main](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Fceliaelazamey-arch%2Fphone-google)

**قبل دمج حزمة التنفيذ:** استخدم زر النشر في المعاينة `/deploy`؛ يشير إلى فرع المصدر الجاري، لا main القديم. Render يدعم الفرع في رابط repo بالشكل `/tree/branch`. [5](https://render.com/docs/deploy-to-render)

1. سجّل الدخول إلى Render ووافق على الوصول للمستودع المطلوب فقط.
2. راجع أن هناك **خدمة web واحدة وخطة free**، بلا disk أو worker أو قاعدة Render مدفوعة/محدودة بـ30 يومًا. إن ظهرت تكلفة أو بطاقة فتوقف.
3. أدخل القيم الست التي يطلبها Blueprint في Dashboard فقط:

| المتغير | القيمة من Aiven |
|---|---|
| MYSQL_HOST | اسم المضيف، لا URL كاملًا |
| MYSQL_PORT | منفذ الخدمة الفعلي |
| MYSQL_DATABASE | اسم القاعدة الجديدة المخصصة |
| MYSQL_USER | اسم المستخدم المصرح له بالقاعدة |
| MYSQL_PASSWORD | كلمة المرور في مخزن الأسرار فقط |
| MYSQL_SSL_CA_BASE64 | شهادة CA بصيغة base64 |

4. يولّد Render `CELIA_MCP_API_TOKEN` و`TOKEN_ENCRYPTION_KEY`؛ `generateValue` موثق كقيمة base64 لـ256 bit. لا نطبعها أو نرسلها للمتصفح. [6](https://render.com/docs/blueprint-spec)
5. احفظ مفتاح التشفير في مخزن أسرار مستقل قبل حذف/إعادة إنشاء الخدمة؛ مفتاح جديد لا يفك رموز OAuth القديمة. لا يوجد نسخ سحري للمفتاح داخل Git.
6. وافق على الإنشاء. `/readyz` لن يعطي نجاحًا حتى تكون MySQL متاحة. إن كانت القاعدة غير فارغة وغير متوافقة، يفشل الإعداد بدل حذف بياناتها.
7. بعد نجاح البداية اضبط `CELIA_DB_INITIALIZE=false` من Dashboard، لأن التهيئة الأولية ليست أداة ترحيل. التحقق في الوضع empty-only لا يعدل قاعدة قائمة متوافقة، لكنه لا يغني عن سياسة نشر وترحيل مستقلة.
8. التحديث التلقائي مُعطل (`autoDeployTrigger: off`)؛ لا تُنشر تغييرات مستقبلية لمجرد دفعها دون مراجعتك.

يحافظ `render.demo.yaml` على المسار التجريبي القديم بلا MySQL، **ولا يُستخدم لبيانات حقيقية أو يُسمّى نشرًا بكامل القدرات**.

## الخطوة 3 — Google وWhatsApp وAI

هذه الخدمات لا تحصل على اعتماديتها بمجرد نشر الخادم، ولا يمكن استخراج رموز الموصلات الخاصة بـArena لإعطائها لتطبيق عام.

- Render يوفر `RENDER_EXTERNAL_URL`؛ يشتق الوضع الكامل callback افتراضيًا كـ`https://<actual-host>/auth/google/callback`. على استضافة أخرى اضبط `APP_BASE_URL` إلى أصل HTTPS الفعلي.
- Google: أنشئ OAuth client بحسابك، وفعّل APIs المطلوبة، واضبط callback مطابقًا؛ أدخل `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` و`APP_OWNER_EMAIL` لدى Render. اتبع README للاتصال المصادق عليه؛ لا توسيع scopes أو حسابات بلا موافقتك.
- Meta/WhatsApp: ابدأ برقم الاختبار المجاني من [Meta Developer Hub](https://whatsappbusiness.com/developers/developer-hub/) قبل نقل الرقم إلى الإنتاج. عنوان Webhook الفعلي هو `https://<actual-host>/webhooks/whatsapp`. إعداد الخادم الكامل يحتاج `WHATSAPP_ACCESS_TOKEN` و`WHATSAPP_PHONE_NUMBER_ID` و`WHATSAPP_APP_SECRET` و`WHATSAPP_VERIFY_TOKEN`، مع `APP_OWNER_PHONE_E164` لحدود أوامر المالك. قيمة `WHATSAPP_API_VERSION` الافتراضية هي `v26.0` (إصدار Graph API الحالي في تاريخ هذه المراجعة)، ويمكن تغييرها عبر إعداد البيئة بعد التحقق من دعم Meta.
- إدارة REST تستخدم `APP_API_TOKEN` إن حددته، وإلا رمز MCP نفسه في **الوضع الكامل الاختياري فقط**. لا يُستخدم الرمز في query string أو رابط.
- Gemini وبقية مزودي الذكاء والأدوات المحمية (`GEMINI_API_KEY`، `AI_GATEWAY_API_KEY`، `DEEPSEEK_API_KEY`، `AGENETROUTERAPI_KEY`، `ELEVENLABS_API_KEY`، `CELIA_VOICE_ID`، `FIGMA_ACCESS_TOKEN`، `YOUR_CODATA_API_KEY`) اختياريون ومربوطون في `render.yaml` عبر `sync: false`؛ ضع المفاتيح في مخزن أسرار Render فقط عند الرغبة بتشغيلها على الخادم العام (أسرار GitHub Actions تعمل داخل مهام GitHub فقط ولا تنتقل تلقائيًا إلى Render). البديل المحلي محافظ وليس نموذجًا توليديًا عامًا، وOllama المحلي غير متاح تلقائيًا على Render.
- مجانية الاستضافة لا تجعل APIs خارجية غير محدودة؛ حصص وتسعير Meta/Gemini وغيرهما تتبع حسابك. لا تفعّل فوترة أو مزوّدًا مدفوعًا ضمن هذا الطلب.
- مفاتيح GitHub Actions **لا تُنقل تلقائيًا** إلى خادم Render. تظهر حقول Meta أعلاه في Blueprint عبر `sync: false`؛ أدخلها في Render Dashboard فقط. للتدقيق الحي أضف الأسرار الأربعة إلى **Settings → Secrets and variables → Actions → Repository secrets**، وأضف `WHATSAPP_API_VERSION=v26.0` كـRepository variable. لا تنشئ المفتاح أو تنسخه إلى Git/واجهة الموقع أو نص المحادثة.
- الاختبار الأول بلا تكلفة: رقم Meta التجريبي، طلب Graph API للقراءة فقط من خدمة التدقيق، والتحقق من GET challenge وتوقيع POST وdedup داخل الاختبارات. المسبار لا يرسل رسالة. اختبار الإرسال الحقيقي يدوي وبموافقة إلى رقم الاختبار فقط، ثم يُسجّل دليل webhook. لا تعتبر إعداد الأسرار دليل اتصال فعلي.
- `WHATSAPP_AUTO_REPLY_ENABLED=false` يبقى افتراضيًا في Render. لا تفعّله قبل ثبوت opt-in وai-opt-in ونافذة 24 ساعة والاختبار الحي. Meta توفر أرقام اختبار مجانية، لكن هذا لا يضمن مجانية كل رسائل الإنتاج؛ قد تُطبق رسوم الرسائل وفق حسابك والسياسات الحالية. تحقق من [صفحة المطورين الرسمية](https://whatsappbusiness.com/developers/developer-hub/) و[سياسة الأسعار](https://developers.facebook.com/docs/whatsapp/pricing/).

## الخطوة 4 — قبول النشر الحقيقي

لا تُغلق مهمة النشر قبل تسجيل الأدلة التالية دون أسرار:

- [ ] رابط HTTPS الفعلي المعاد من المزوّد يفتح خارجيًا، لا رابط مخمّن.
- [ ] `/version` يطابق commit/نسخة التنفيذ المقصودة.
- [ ] `/readyz` يعيد 200 مع `storage.mode=mysql` و`durable=true`.
- [ ] `/api/deployment` يثبت `fullApiMounted=true`؛ الرمز غير الصحيح يرفض REST وMCP.
- [ ] Webhook يتحقق من bytes الأصلية، ثم يُختبر حساب Meta فعليًا بعد الموافقات.
- [ ] Google OAuth فعلي مقيد بالمالك، وتجربة قراءة مصرح بها دون بيانات حساسة في التقرير.
- [ ] إعادة تشغيل التطبيق لا تفقد البيانات المؤكدة، ونسخة مستقلة من قاعدة الحساب استعيدت فعلًا.
- [ ] قيود الكلفة والاحتفاظ وأسرار التشفير محفوظة، ولا مطالبة بقدرة أو uptime غير محدودين.

`allCapabilitiesVerified=false` في التقرير مقصود: endpoint القراءة لا يجمع دليل قبول نشر خارجي أو موافقات إنتاج ولا يدعي ذلك. أدلة الاستخدام/الإعداد الجزئية تظل جزئية.

## اختبارات القبول المنفذة آليًا

`npm test` يغطي الوحدة/المسارات وTLS وقفل التهيئة ورفض قاعدة غير متوافقة. `npm run test:browser` يغطي صفحة النشر والهاتف والتقرير القديم وPages وإتاحة آلية.

`npm run test:mysql` يعمل **فقط** باختيار صريح وخادم MySQL 8.4 محلي في حاوية CI. ينشئ ويحذف قواعد مصطنعة بأسماء عشوائية محصورة؛ يرفض مضيفًا بعيدًا. يختبر:

- رفض شهادة MySQL حقيقية ذات CA موثوقة لكن اسم مضيف خاطئ؛ الثقة بالمُصدر وحدها غير كافية.
- إنشاء الجداول الأصلية ورفض قاعدة غير متوافقة دون تعديلها.
- consent وWebhook موقع وتكراره دون تكرار الصف.
- transaction rollback وتشفير رموز مصطنعة.
- إعادة تشغيل التطبيق واتصال جديد مع بقاء البيانات.
- قراءة الكود السابق 0.2.0 لنفس schema1 وبقاء عقود أدوات MCP الاثنتي عشرة.
- mysqldump ثم restore فعلي في قاعدة منفصلة، ومقارنة العربية والموافقات وفك التشفير.

الأثر المحفوظ في CI هو `.validation-artifacts/mysql-evidence.json` المنقح فقط، لا dump ولا مفاتيح. نجاح هذه التجربة **لا يثبت نسخة إنتاج أو نشرًا في حساب Render/Aiven**.

## الرجوع وحدوده

بيانات schema1 لم تتغير. تبقى آلية إصدار digest والقفل وrollback/recover كما في [الدليل](releases-and-recovery.md). Render يستخدم نشره/رجوعه المقدم من المنصة، لا أوامر Docker المحلية مباشرةً.

**تنبيه مهم:** قراءة0.2.0 في CI تمت على SQL محلية معزولة دون TLS إنتاجية. النسخة لا تعرف متغير CA الجديد، فلا يُستنتج منها إمكان اتصال Aiven عند الرجوع؛ قد يرفض TLS إلى أن توجد خطة ثقة مدققة. لا تخفّض التحقق لإجباره على العمل.

نسخة 0.2.0 لا تعرف خيار تجميع REST على منفذ MCP؛ الرجوع إليها يعيد MCP القديم ولا يَعِد ببقاء مسارات REST الجديدة على نفس المنفذ. يلزم سلف كامل سليم ومتوافق، أو إعادة خادم REST المستقل وفق خطة تشغيل مجرّبة. أول نشر ليس له نسخة سابقة مخترعة. لا يُعاد إرسال إجراء خارجي أثناء rollback، ولا تُستعاد بيانات بعملية رجوع كود.
