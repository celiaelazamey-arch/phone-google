# خطة النشر المجاني — صفحة الهبوط الفاخرة (سيليا 2026)

> **الهدف:** صفحة هبوط احترافية مركّزة على التحويل لمنتج **«سيليا 2026 — مساعد الهاتف + Google»**،
> لجمهور **أصحاب الأعمال والفرق العربية الصغيرة**، بهدف أساسي هو **فتح التجربة الحية المجانية** (`/`).
> **الميزانية المستهدفة: ٠ دولار** — بلا بطاقة، بلا أسرار في Git.
> هذا الملف هو «الخطة» ثم «سجل التنفيذ الفعلي» كما نُفِّذ داخل الجلسة دون الرجوع للمالك.

---

## ١) قرارات المحتوى (استبدلت العناصر النائبة من المشروع نفسه)

| العنصر النائب | القرار المنفَّذ |
|---|---|
| `[Brand/Product Name]` | **سيليا 2026 — مساعد الهاتف + Google (MCP)** (اسم المنتج الفعلي في الواجهة) |
| `[Target Audience]` | أصحاب الأعمال والفرق العربية الصغيرة (عيادات، متاجر، شركات خدمات) التي تستقبل عملاء عبر واتساب وتعمل على Google |
| `[Primary Goal]` | تحويل الزائر إلى **التجربة الحية المجانية** في `/` (ثم حجز إعداد احترافي من نموذج CTA) |

## ٢) بنية الصفحة المنفَّذة (`public/landing.html` + `landing.css` + `landing.js`)

- شريط تنقل زجاجي لاصق + قائمة جوال + مؤشر تقدم تمرير + تمييز القسم النشط.
- Hero: عنوان تحويل عربي، زرّا CTA، عدّادات متحركة (١٢ أداة · ٢٤ ساعة · ٢٥٦-بت · ١٠٠٪)،
  ونموذج هاتف CSS بحوار واتساب حيّ (كتابة… فقاعات) وبطاقات زجاجية عائمة.
- إثبات اجتماعي: شريط تكاملات متحرك (Gmail / Drive / Calendar / Contacts / WhatsApp / Gemini / MCP / MySQL).
- مزايا Bento (٦ بطاقات بتوهّج تتبّع المؤشر) → عرض بتبويبات تفاعلية (واتساب / Google / MCP) + ٣ خطوات.
- شبكة الأدوات الـ١٢ الحقيقية من `MCP_TOOLS` → فوائد + بطاقة أمان (AES-256-GCM / HMAC-SHA256).
- آراء عملاء (٣) → أسعار بتبديل شهري/سنوي (يعمل بـ JS) → أسئلة شائعة أكورديون (٦).
- CTA أخير بنموذج تحقّق كامل (**لا يرسل أي بيانات خارجيًا** — حفظ محلي تجريبي معلن) → تذييل كامل + حالة حيّة من `/health`.
- **حركة:** كشوف تمرير متدرّجة (`IntersectionObserver` + `--d`)، كرات محيطية، إمالة هاتف، أزرار مغناطيسية، `prefers-reduced-motion` محترَم.
- **إتاحة:** RTL كامل، تخطٍّ للمحتوى، تبويبات بلوحة المفاتيح، `aria-*`، تركيز مرئي، الصفحة تُقرأ كاملة دون JS.
- **توافق صارم:** لا سكربت مضمّن ولا `onclick` (CSP: `script-src 'self'`)، لا صور خارجية (هاتف CSS فقط) — نفس الملفات تعمل على Node وPages.

## ٣) خطوات النشر المجاني (بالترتيب التنفيذي)

### الخطوة ١ — التكامل مع الخادم الحالي

1. ملفات `public/landing.*` جديدة لا تلمس مساحة الوكيل (`/` يبقى التطبيق — صفر كسر).
2. مسارات جديدة في `src/celia-ui.js`: `GET /landing`، `/landing.html`، `/landing.css`، `/landing.js` (+ `/index.html` للتماثل مع Pages).
3. تحديث `scripts/build-pages.mjs`: تحويل `./landing` → `./landing.html` في البناء الثابت (البناء ينسخ كل `public/*.html` تلقائيًا ويحقن طبقة المحاكاة، فتصبح الصفحة ضمن `dist/` دون أي خطوة إضافية).

### الخطوة ٢ — المعاينة الحية الفورية (٠ تكلفة، الآن)

```bash
npm install
CELIA_MCP_DISABLE_MYSQL=true CELIA_MCP_API_TOKEN=$(openssl rand -hex 32) \
CELIA_MCP_HOST=0.0.0.0 CELIA_MCP_PORT=3010 node src/celia-mcp.js
# صفحة الهبوط: http://localhost:3010/landing  · المساحة: http://localhost:3010/
```

### الخطوة ٣ — التحقق الآلي قبل أي نشر

```bash
npm run check                                  # فحص بناء كل ملفات JS (شامل landing.js)
npm test                                       # حزمة الاختبارات كاملة
npm run build:pages                           # توليد dist/ شاملًا landing.*
grep -rEI "AIza[0-9A-Za-z_-]{20,}|APP_API_TOKEN=" dist   # يجب أن يكون فارغًا
```

### الخطوة ٤ — النشر الدائم المجاني على GitHub Pages (المسار الأساسي)

1. دفع الفرع ودمجه إلى `main` عبر Pull Request → سير عمل `.github/workflows/pages.yml` يبني ويختبر وينشر تلقائيًا.
2. محاولة تفعيل Pages برمجيًا عبر API (`POST /repos/{owner}/{repo}/pages` بقيمة `workflow`).
   - إن رفض GitHub (403 «Resource not accessible by integration») فالتفعيل الأول يحتاج **نقرة مالك واحدة فقط**:
     **Settings → Pages → Build and deployment → Source: GitHub Actions** ثم **Actions → Deploy (GitHub Pages) → Run workflow**.
3. الروابط بعد النشر:
   - صفحة الهبوط: `https://celiaelazamey-arch.github.io/phone-google/landing.html`
   - المساحة الحية: `https://celiaelazamey-arch.github.io/phone-google/`

### الخطوة ٥ — بديل دائم بخادم Node كامل (مجاني أيضًا)

- `render.yaml` + `Dockerfile.mcp` جاهزان: Render ← New Blueprint ← ربط المستودع ← تصبح الصفحة على `https://<service>.onrender.com/landing`.
- نفس صورة Docker تعمل على Koyeb / Fly.io / Hugging Face Spaces.

### الخطوة ٦ — التحقق بعد النشر

```bash
curl -I https://celiaelazamey-arch.github.io/phone-google/landing.html   # 200 text/html
curl -I https://celiaelazamey-arch.github.io/phone-google/landing.css    # 200 text/css
curl -I https://celiaelazamey-arch.github.io/phone-google/landing.js     # 200
curl -s https://celiaelazamey-arch.github.io/phone-google/health.json    # status ok
```

## ٤) سجل التنفيذ الفعلي في هذه الجلسة

| الخطوة | الحالة | الدليل |
|---|---|---|
| استبدال العناصر النائبة وبناء الصفحة | ✅ منفَّذة | `public/landing.html` · `landing.css` · `landing.js` (لا سكربت مضمّن، لا `onclick`) |
| ربط الخادم + بناء Pages | ✅ منفَّذة | `src/celia-ui.js` (`/landing*`) · `scripts/build-pages.mjs` (`./landing` ← `landing.html`) · رابط «🚀 صفحة الهبوط» في `index.html` |
| اختبارات + بناء `dist/` | ✅ منفَّذة | `npm run check` ناجح · `npm test` **٢٤/٢٤** · `build:pages` يضم `landing.html` · مسح أسرار `dist/` نظيف |
| معاينة حيّة | ✅ منفَّذة | `0.0.0.0:3010/landing` → ‏200‏ + CSS/JS/‏`/health`‏ 200 تحت CSP الصارم؛ ونسخة `dist/` الثابتة مختبرة محليًا بنفس النتائج |
| دفع + PR + دمج إلى `main` | عبر PR من فرع الجلسة | الدمج إلى `main` يُشغّل `pages.yml` تلقائيًا (بناء ← اختبارات ← نشر) |
| تفعيل GitHub Pages | ⚠️ نقرة مالك واحدة متبقية | جُرّب فعليًا: ‏`POST /pages` ← **403 Resource not accessible by integration** (إنشاء موقع Pages أول مرة يتطلب صلاحية مالك لا يملكها توكن الأتمتة) |

> لا يُزعم هنا نشرٌ لم يحدث: كل ما يمكن أتمتته منفَّذ ومختبَر، والعائق الوحيد المتبقي هو
> قيد منصّة GitHub الموثّق أعلاه. بعد نقرة **Settings → Pages → GitHub Actions** الواحدة
> ينشر سير العمل الجاهز تلقائيًا عند أي دفع إلى `main` — دون أي تغيير إضافي في الشيفرة.
