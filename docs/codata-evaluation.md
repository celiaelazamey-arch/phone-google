# تقييم Codata والمسار المجاني — توضيح قبل أي اعتماد

**التاريخ:** 27 أكتوبر 2026 · **الحالة:** تقييم مبدئي غير منفذ، لا افتراض دعم مجاني شامل
**السياق:** وصف Codata المقترح لم يُرسل بعد لأن اتصال Codata غير متاح لهذه الجلسة في Arena. هذه الوثيقة توضّح القدرات والحدود والتكلفة قبل أي تنفيذ، وفق شرط المستخدم المالي.

## الخلاصة التنفيذية

- **لا نفترض أن Codata يدعم جميع المتطلبات مجانًا.** أي منصة تروّج طبقة مجانية قد تقيّد الميزات (قواعد، تخزين دائم، MCP، OAuth/Webhook) أو تطلب ترقية لاحقًا. لا نعتمدها دون فحص وثائقها الرسمية وتجربة مصادق عليها.
- **المسار المجاني المُتحقق حاليًا يبقى:** Render Free (خدمة Node واحدة + نطاق فرعي HTTPS) + Aiven Free MySQL + GitHub Actions/pages للواجهة الثابتة. هذا المسار مُختبر في CI ولا يطلب بطاقة دفع في وثائقه الحالية، لكنه محدود (نوم بعد خمول، موارد قليلة).
- **Codata مساحة عمل مستقلة:** معرف المساحة المشار إليها `6ae05ac477ceef820d0c5831` — يلزم تسجيل دخول المالك واختيار عميل يدعم MCP وإكمال OAuth داخل Codata نفسه. لا يمكن تسجيل هذا الاتصال أو إنشاء مخطط قاعدة داخل Arena بأدواتها الحالية، ولن نُنشئ مخططًا وهميًا وندّعي تطبيقه.

## ما طُلب لـ Codata

> سيليا مساعد عربي بواجهة مناسبة للهاتف والكمبيوتر، يستخدمه مالك واحد لإدارة التفاعل مع خدمات Google وWhatsApp عبر واجهة ويب وأدوات MCP.
>
> يربط المالك حساب Google باستخدام OAuth للبحث في البريد والملفات وجهات الاتصال، وقراءة المواعيد وإنشاء موعد مصرح به. يستقبل رسائل WhatsApp ويتحقق من توقيعها ويمنع تكرارها، ويسمح بالإرسال الفردي وفق الموافقات ونافذة الخدمة. معالجة الرسائل بالذكاء الاصطناعي تتطلب موافقة منفصلة، مع بديل محافظ عند تعطل المزوّد.
>
> نحتاج حفظًا دائمًا وآمنًا للمحادثات والتقدم والموافقات ونتائج العمليات، وحماية بيانات الاعتماد، ونسخًا احتياطية قابلة للاستعادة. يجب ألا يعيد استئناف التطبيق إرسال رسالة أو إنشاء موعد بصورة عمياء.
>
> التطوير تدريجي فوق النظام الحالي، مع الحفاظ على تكاملاته وعقوده وبياناته، وإصدارات قابلة للرجوع وعزل للأعطال. لا نقل أو حذف للبيانات قبل مراجعة خطة التوافق والاستعادة. لا تسجيل عام أو فرق أو مدفوعات مطلوبة حاليًا؛ احتياجات رفع الملفات والبريد الإضافي والجدولة تُوضَّح قبل اعتمادها.
>
> الشرط المالي: مسار مجاني دون بطاقة دفع أو ترقية تلقائية. يجب توضيح قدرات Codata وحدوده وتكلفته الفعلية قبل اعتماد أي تنفيذ، دون افتراض أنه يدعم جميع المتطلبات مجانًا.

## ماذا تغطي هذه المتطلبات في النظام الحالي

| المتطلب | حالة سيليا الحالية (0.2.1 / schema1) | ملاحظة مسار Codata |
|---|---|---|
| واجهة هاتف/حاسوب + MCP | موجودة: `/studio` و`/landing` و`/system` و`/deploy` + 12 أداة MCP + stdio/HTTP | Codata قد يوفر واجهة/استضافة بديلة، لكن لم نتحقق من دعم MCP streamable/stdio أو حدوده |
| Google OAuth (بحث بريد/ملفات/جهات، مواعيد وقراءة+إنشاء حدث واحد) | موجود مع state أحادي الاستخدام، تشفير AES-GCM للرموز، تحقق بريد المالك | يحتاج callback HTTPS ثابت؛ أي استضافة (Render أو Codata) يجب أن توفر `https://<host>/auth/google/callback` مطابقًا |
| WhatsApp webhook + HMAC + منع تكرار + إرسال فردي بموافقة ونافذة 24س | موجود: تحقق HMAC على raw bytes، `provider_message_id` فريد، موافقتان منفصلتان، رفض خارج النافذة | Webhook يجب أن يكون علنيًا `https://<host>/webhooks/whatsapp`؛ لا نشر دون عنوان عام موثق |
| AI اختياري بموافقة منفصلة + بديل محافظ | موجود: `auto` (Gemini → Ollama → قواعد) مع قاطع ومهلة وعزل؛ لا إرسال بدون `ai_opted_in` | أي مزوّد Codata للـ AI يحتاج سياسة وصول وحصص وتكلفة واضحة، لا استدعاء ضمني |
| حفظ دائم للمحادثات والتقدم والموافقات ونتائج العمليات | **مخطط وغير منفذ:** الموافقات والرسائل محفوظة في MySQL، لكن محادثات الاستوديو والـ checkpoints وoutbox ما زالت مهام DATA-002/DATA-003 | Codata إن وفّر DB مُدارًا، يجب توضيح: نوع القاعدة، تشفير، نسخ/استعادة، ملكية البيانات، وإمكان تصديرها |
| حماية بيانات الاعتماد + نسخ قابلة للاستعادة | موجود جزئيًا: تشفير رموز Google، TLS/CA لـ MySQL، dump/restore مصطنعة في CI؛ نسخة حساب المالك غير مجرّبة بعد | Codata يجب أن يوضح أين تُخزن الأسرار (مخزن منفصل أم DB)، وهل النسخ مشفرة وقابلة للاستعادة خارج المنصة |
| عدم إعادة الإرسال/الموعد عند الاستئناف | موجود جزئيًا: OAuth state لمرة واحدة + dedup للرسائل الواردة؛ الإرسال/الموعد الآن يُحصّن بمفتاح تفرد (انظر src/idempotency.js) | أي منصة يجب أن تضمن أن إعادة التشغيل لا تعيد أثرًا خارجيًا بصورة عمياء |
| تطوير تدريجي + إصدارات رجوع + عزل أعطال | موجود: SemVer، سجل إصدارات، قاطع/مهلة/تزامن، `/system` | Codata يجب أن يدعم نشرًا بإصدارات وأمر رجوع موثق، لا نشرًا بلا سجل |
| لا نقل/حذف بيانات قبل مراجعة التوافق | سياسة متبعة: تهيئة `empty-only` لقاعدة فارغة فقط، ترفض إصلاح قاعدة غير متوافقة | لا نستخدم أدوات نقل Codata قبل فحص توافق schema1 واختبار restore معزول |
| لا تسجيل عام/فرق/مدفوعات حاليًا | الوضع الحالي: مالك واحد، لا multi-tenant | إن فرضت Codata اشتراك فريق أو حد مستخدمين، يُعلن كعائق مالي قبل التنفيذ |
| رفع ملفات/بريد إضافي/جدولة | غير مفعّل؛ يُوضح قبل اعتماده | Codata إن عرض هذه الميزات، يجب بيان حصصها وتكلفتها وحدودها |

## قدرات Codata وحدوده وتكلفته — ما يجب توضيحه قبل الاعتماد

1. **الخطة المجانية الفعلية:** هل توجد خطة مجانية دائمة دون بطاقة؟ ما حدودها (مساحة DB، نطاق ترددي، ساعات تشغيل، عدد طلبات MCP)؟ هل تتوقف بعد خمول؟ رابط التوثيق الرسمي.
2. **الدفع والترقية:** هل يطلب بطاقة للتحقق؟ هل توجد ترقية تلقائية عند تجاوز الحصة؟ هل يمكن البقاء على المجاني صراحة؟
3. **MCP والواجهات:** هل يدعم عميل MCP (HTTP + stdio) مع مصادقة Bearer؟ هل يدعم Webhook خام (raw body) لـ HMAC؟
4. **OAuth والنطاقات:** هل يوفر عنوان HTTPS ثابتًا وموثوقًا لـ callback/webhook؟ هل يسمح بإعداد متغيرات بيئة للأسرار دون كشفها في الواجهة؟
5. **قاعدة البيانات:** نوعها (MySQL/Postgres)، تشفير في الراحة، TLS، نسخ احتياطي، PITR، تصدير/استيراد، حدود الحجم.
6. **الخصوصية والملكية:** أين تُخزن البيانات جغرافيًا؟ هل يمكن تصديرها وحذفها بالكامل؟ هل تُستخدم لتدريب نماذج؟
7. **الإصدارات والرجوع:** هل يوجد سجل إصدارات وصور ثابتة وأمر رجوع؟ ماذا يحدث للبيانات عند الرجوع؟
8. **الاعتمادية:** هل الاستضافة تنام؟ ما SLO المعلن؟ هل يوجد تنبيه عند الفشل؟

**لن نعتمد Codata قبل إجابات موثقة على هذه النقاط، ولن ننقل بيانات أو نحذفها قبل خطة توافق واستعادة مجرّبة.**

## الخطوة اللازمة للمتابعة (كما في رسالة المستخدم)

> استخدم **Connect an agent** داخل مساحة Codata `6ae05ac477ceef820d0c5831` لاختيار عميل يدعم اتصال MCP وإكمال موافقة OAuth.

- هذه خطوة يقوم بها المالك داخل واجهة Codata، لا عبر Arena.
- لا نستطيع تسجيل هذا الاتصال داخل Arena بالأدوات الحالية، ولن ندّعي أن مخططًا أُنشئ أو طُبّق.
- بعد اكتمال الموافقة، يمكن تزويدنا برابط الخدمة الفعلي والتوثيق الرسمي للخطة المجانية للمراجعة.

## حدود الربط البرمجي الحالي لسر `YOUR_CODATA_API_KEY` (في 0.2.1+)

تم ربط سر المستودع `YOUR_CODATA_API_KEY` (والاسم البديل `CODATA_API_KEY`) في `src/secrets-hub.js` بوصفه **موصل حالة وفحص للقراءة فقط** محميًا برمز المالك (`GET /api/codata/status` وأداة MCP الاختيارية `codata_status` لمعرّف المساحة `6ae05ac477ceef820d0c5831`):

- `primaryTransactionalStore: false` — تبقى MySQL قاعدة المعاملات الأساسية الوحيدة وفق `DEC-002`.
- `automaticMigrationAllowed: false` — لا يجري أي نقل تلقائي أو كتابة لرسائل العملاء أو الموافقات أو رموز OAuth إلى Codata.
- عند ضبط `CODATA_BASE_URL` يمر العنوان عبر حارس HTTPS الصارم المضاد لـSSRF (`normalizeHttpsApiUrl`) خلف قاطع الدائرة `codata` وبمهلة محدودة (`DEFAULT_POLICY`).

## التوصية الحالية

- **الاستمرار على النظام الحالي (0.2.1) + المسار المجاني الموثق (Render + Aiven) للاختبار والنشر المبدئي**، مع تحسينات أمان إضافية (مفاتيح تفرد لمنع إعادة الإرسال).
- **تأجيل أي نقل بيانات إلى Codata حتى:** (أ) توضيح حدوده وتكلفته كتابةً، و(ب) نجاح اختبار توافق واستعادة معزول، و(ج) موافقة صريحة على خطة الترحيل.
- **لا رفع ملفات/بريد إضافي/جدولة جديدة قبل توضيح الحاجة والحصص والتكلفة.**
