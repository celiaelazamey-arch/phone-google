## 0. ماذا يعني «منافس مانوس» فعلًا؟ (تعريف قابل للقياس)

مانوس (Manus) وكيل عام مستقل يتميز بست قدرات جوهرية. «نستحق اللقب» يوم نحقق **المعايير القابلة للقياس** التالية، لا يوم نكتب صفحة هبوط:

| # | قدرة مانوس | معيار القبول عندنا (قابل للفحص الآلي) |
|---|---|---|
| C1 | تنفيذ مهام متعددة الخطوات باستقلالية حقيقية بنموذج حي | ≥ 85% نجاح على مجموعة تقييم عربية ≥ 200 حالة عبر الحلقة الفعلية بمزود حي (امتداد `eval:ai` الحالي الذي يعمل اليوم بمزود وهمي 120/120) |
| C2 | حاسوب سحابي معزول لكل مهمة: shell + ملفات + كود | `sandbox.exec` موصول بحلقة الوكيل، تشغيل Python/Node فعلي داخل العزل، artifacts مُصدَّرة ومثبتة ببصمة في سلسلة الأدلة |
| C3 | تصفح ويب حقيقي (قراءة، نقر، استخراج) | متصفح يعمل داخل العزل بسياسة egress صريحة؛ صفحة `/computer` تعرض تتبعًا **حيًا** بدل «توضيحي» |
| C4 | مخرجات ملموسة: تقارير، جداول، عروض، مواقع | أداة `artifact.create` تولّد ملفات (MD/CSV/HTML/صور) تُسلَّم للمالك عبر Drive أو رابط موقّع، لكل منها `content_hash` في الأدلة |
| C5 | مهام مجدولة ودورية غير متزامنة | ربط `cron-job.org` القائم بحلقة الوكيل: مهمة تُجدول وتعمل والمالك نائم، والنتيجة تصله على WhatsApp |
| C6 | تجربة «أرسل واذهب» من أي جهاز | WhatsApp = قناة إطلاق مهام كاملة (موجود جزئيًا)، وواجهة `/agent` تعمل PWA على الهاتف بتتبع حي |

**ما لن ننافس فيه عمدًا (وهو سلاحنا):** مانوس صندوق أسود بلا حوكمة. نحن نحتفظ بـ:
سلسلة أدلة SHA-256 غير قابلة للعبث، بوابة موافقات للمالك، مُتحقِّق مستقل (`PASS/BLOCK/UNKNOWN`)،
مصالحة بشرية لكل أثر غير محسوم، وعربية أولًا، وتكلفة بنية 0$ بلا بطاقة. **«مانوس الذي تستطيع تدقيقه»** — هذا هو الموقع التسويقي.

## 1. جرد صادق: أين نقف اليوم مقابل كل معيار

| المعيار | موجود ومختبر اليوم | الفجوة الصلبة |
|---|---|---|
| C1 استقلالية | حلقة Plan→Act→Observe→Verify→Deliver دائمة (M1) بقفل lease واستئناف وميزانيات؛ شريحة Planner-Provider قابلة للحقن (AI-002) مختبرة بمزود وهمي 10/10؛ `eval:ai` 120/120 محليًا | المخطط الافتراضي **حتمي تجريبي**؛ لا نموذج حي موصول بالتخطيط؛ لا إعادة تخطيط محكومة (WP-3.2) ولا موازاة قراءات (WP-3.3) |
| C2 حاسوب معزول | Backend عزل كامل (`sandbox.js`: namespaces + chroot + حدود موارد + شبكة deny) مختبر 17/17 على Linux | **غير موصول** بـ`sandbox.exec` في مسار الوكيل؛ workspace محدود 8MiB؛ لا Python؛ لا تصدير artifacts للمالك |
| C3 تصفح | صفحة `/computer` شرح بصري صادق؛ `celia-google-spider` (Python/Playwright) موجود كمشروع منفصل | لا متصفح داخل العزل؛ لا egress proxy معتمد (السياسة ترفض أي allowlist غير فارغة عمدًا)؛ السبايدر غير مربوط بالحلقة |
| C4 مخرجات | الوكيل يسلّم نصوصًا وأحداث Calendar (موصل واحد)؛ KB/SQLite+FTS5 للمعرفة | لا توليد ملفات؛ لا رفع Drive من الحلقة؛ لا قوالب تقارير/عروض |
| C5 جدولة | تكامل cron-job.org مهيأ ومتحقق (12/12 خدمة)؛ صفحة `/cron` | الجدولة لا تُطلق **تشغيلات وكيل**؛ لا «مهمة دورية بعقد هدف» |
| C6 قنوات | WhatsApp webhook رسمي بأوامر مالك عربية + Gemini؛ `/agent` بتتبع خطوات وp50/p95 | WhatsApp لا يفتح خيط وكيل كامل (WA-006 خلف علم مطفأ)؛ لا PWA/إشعارات؛ لا تتبع حي push (polling فقط) |
| بنية | حافة Cloudflare Workers+D1 منشورة بـ0$؛ MySQL كامل غير منشور (HOST-003 محجوب ببطاقة) | الحلقة الكاملة (runtime) لا تعمل على الحافة؛ بلا مضيف دائم للوكيل لا يوجد C2/C3 إنتاجيان |

**الخلاصة:** الهيكل العظمي الحوكمي — وهو أصعب ما في وكيل موثوق — **منجز ومختبر**. الفجوة كلها في «العضلات»:
نموذج حي، تنفيذ معزول موصول، متصفح، مخرجات ملفية، وقناة إطلاق كاملة. هذه هي الخطة.
