# من «مساعد موصول بأدوات» إلى «وكيل متكامل» (هدف على نمط Manus)

**التاريخ:** 27 أكتوبر 2026 · **النسخة:** 1.0 — وثيقة اتجاه، **ليست** إعلان ميزات منجزة.
**خط الأساس:** `5dead2c` (دمج PR #26) · التطبيق `0.2.1` · `schema: 1` · حزمة `celia-google-spider` 0.1.0.

> هذه الوثيقة تجيب سؤالًا واحدًا: ما الذي يفصل النظام الحالي عن نظام وكيل متكامل على نمط Manus،
> وما الترتيب الواقعي للمرور بينهما **بدون** اختلاق قدرات أو ادعاء نشر. الحالة التنفيذية تبقى في
> [BACKLOG](continuity/BACKLOG.md)، والتركيز الحالي في [STATE](continuity/STATE.md).

## 1. ما «مانوس» في جوهره — لا في واجهته

Manus ليس «دردشة بأدوات»، بل **حلقة تنفيذ مستقلة** تعمل على مهمة كاملة يعطيها المستخدم في جملة واحدة:
تخطّط، تنفّذ خطوة، تراقب النتيجة، تعدّل الخطة، وتُسلّم **مخرجًا** (ملف/تقرير/تغيير في خدمة خارجية)، مع
استمرار المهمة بعد انقطاع، وعرض مباشر للخطوات، وحدود تنفيذ معزولة (آلة/حاوية يُشغّل فيها الكود والملفات).

القدرات السبع التي تصنع الفرق، مرتبة بالأثر:

| # | القدرة | معنى عملي قابل للاختبار |
|---|---|---|
| 1 | حلقة Plan → Act → Observe | مهمة واحدة تنتج سلسلة خطوات متعددة (>1 أداة) بقرار ذاتي، لا استدعاء أداة واحدة لكل رسالة |
| 2 | حالة دائمة ومهام قابلة للاستئناف | إعادة تشغيل العملية أو الجهاز لا تُفقد المهمة؛ تُستأنف من آخر خطوة مؤكدة |
| 3 | تسليم مخرجات (Artifacts) | ملفات/تقارير/جداول تُنتَج وتُخزَّن وتُسلَّم برابط صالح ومدة انتهاء |
| 4 | مساحة تنفيذ معزولة | تشغيل كود/أوامر/معالجة ملفات داخل عزل بلا وصول للمضيف ولا شبكة مفتوحة |
| 5 | أدوات قراءة **وكتابة** في الأنظمة الخارجية | Google/WhatsApp/Drive بصلاحيات فعلية، لا قراءة فقط، مع بوابة موافقة |
| 6 | شفافية تشغيل | بث حي للخطوات، تكلفة/توكن لكل مهمة، إلغاء فوري، سجل قابل للتدقيق |
| 7 | تعدد المستخدمين والحدود | عزل ملكية لكل مستخدم، حصص، وسياسة احتفاظ — شرط أن يكون منتجًا لا تجربة فردية |

> **تحديث 2026-10-27 (لاحق):** نُفِّذ هيكل M1 فعليًا ومُختبر محليًا (حلقة دائمة، استئناف، lease، إلغاء، ميزانيات، بوابة
> مخاطر، SSE، سجل ترحيل) على مخزن SQLite صريح، مع مسارات `/api/agent/*` وواجهة `/agent`. **لم يُنفَّذ:** مخطط لغوي،
> MySQL حي، أثر خارجي، عزل، artifacts، استئناف تلقائي عند الإقلاع. راجع [docs/agent-runtime.md](agent-runtime.md)
> وDEC-013؛ الصف `AGENT-001` ما زال `جارٍ`، والوصف «مثل Manus» يبقى ممنوعًا.

## 2. ما هو موجود الآن بالدليل

| المكوّن | الحالة الفعلية | الملف/الدليل |
|---|---|---|
| خادم HTTP | Express 5 / ESM، مسارات صحية وإصدار وتشخيص وMCP على `/mcp` (GET/POST) وواجهة أدوات | `src/operations.js` · `src/celia-mcp.js:1023-1060` |
| أدوات | 12 أداة MCP افتراضية + 4 اختيارية (`CELIA_EXTENDED_MCP_TOOLS`) تغطي Google (Gmail/Drive/Calendar/Contacts)، WhatsApp، AI، صوت، Figma، Codata، أسرار | `src/celia-mcp.js` · DEC-010 |
| Google OAuth | تخزين رموز مشفّر AES-256-GCM، جدول `google_credentials`، نطاقات قراءة + إنشاء تقويم محدود | `src/security.js:18` · `sql/schema.sql` |
| WhatsApp | تحقّق HMAC، تفادي تكرار، **موافقتان** (تحدث + AI) قبل أي رد آلي | `src/whatsapp.js` · `src/policy.js` |
| البيانات | MySQL بخمسة جداول فقط: `app_users`، `oauth_states`، `google_credentials`، `whatsapp_contacts`، `whatsapp_messages` | `sql/schema.sql` |
| المرونة | قواطع دوائر، مهل، حدود تزامن، لا سقوط صامت لذاكرة | `src/resilience.js` · `src/ollama.js` |
| النشر | حزم موقّعة، SBOM، تبديل/تراجع، Blueprint مجاني لخدمة واحدة | `scripts/release.mjs` · `render.yaml` |
| الواجهة | استوديو + صفحة هبوط + لوحة `/system` + `/deploy`، RTL وأصول محلية | `public/` |

### الفجوة الحقيقية: لا حلقة، لا ذاكرة مهمة، لا تنفيذ

النظام اليوم **مساعد موصول بأدوات جيدة**: كل تفاعل = استدعاء واحد (أو رد AI واحد). لا يوجد:
`agent run`، ولا خطوات، ولا checkpoints، ولا استئناف، ولا artifacts، ولا عزل تنفيذ، ولا بث خطوات، ولا
تكلفة لكل مهمة. أي وصف له بأنه «وكيل مثل Manus» الآن غير صحيح، ويجب ألا يُكتب في أي وثيقة أو عرض.

## 3. المعمارية المقترحة (ما يُبنى فعلًا)

```
قنوات: Web (SSE) · WhatsApp · MCP
        │
   ┌────▼───────────────────────────────────────────┐
   │ Orchestrator (src/agent/runtime.js)            │
   │ مهمة → خطة → خطوة → نتيجة → قرار → تسليم       │
   │ ميزانيات: خطوات/وقت/تكلفة · إلغاء · استئناف     │
   └────┬──────────────┬───────────────┬────────────┘
        │              │               │
  Tool Registry    Policy/Approvals   Artifact store
  (MCP + داخلي)    (تصنيف المخاطر)     (ملفات + انتهاء)
        │
  ┌─────▼──────────────┐      ┌───────────────────────┐
  │ خدمات خارجية       │      │ Sandbox worker         │
  │ Google · WhatsApp  │      │ حاوية لكل مهمة، بلا    │
  │ AI · صوت · Figma   │      │ شبكة إلا بقائمة سماح   │
  └────────────────────┘      └───────────────────────┘
```

**نماذج البيانات الجديدة (schema 2 — تتطلب migration ledger من COMP-003، لا ALTER عشوائي):**

- `agent_threads` (معرف، مالك، عنوان، حالة، آخر نشاط)
- `agent_messages` (خيط، دور، محتوى، `client_message_id` فريد، ترتيب)
- `agent_runs` (خيط، حالة `queued/running/waiting_approval/succeeded/failed/cancelled`، ميزانيات، تكلفة)
- `agent_steps` (تشغيل، رقم الخطوة، نوع `plan/act/observe/decide/deliver`، ملخص آمن)
- `agent_tool_runs` (تشغيل، أداة، معاملات منقّحة، `idempotency_key`، حالة، `outcome_unknown` عند الشك)
- `agent_outbox` + `agent_approvals` (أثر خارجي معلّق لا يُنفَّذ قبل موافقة، ولا يُعاد تلقائيًا)
- `agent_artifacts` (تشغيل، اسم، نوع MIME، حجم، مفتاح تخزين، انتهاء)

**قواعد غير قابلة للتفاوض في التصميم:**

1. **لا إعادة تنفيذ عمياء:** أي أثر خارجي انتهت مهلته أو انقطع اتصاله يُوسم `outcomeUnknown` وينتظر مصالحة أو
   مراجعة بشرية — استمرارًا لقاعدة `AGENTS.md`.
2. **تصنيف مخاطر إلزامي لكل أداة:** قراءة / كتابة داخلية / أثر خارجي / أثر غير قابل للتراجع. الثالث والرابع
   يحتاجان موافقة صريحة (وإن كانت مسبقة ضمن نطاق محدد، فتُسجّل مرة واحدة بحد زمني).
3. **العزل قبل الأتمتة:** لا تشغيل كود مولّد من نموذج قبل وجود حاوية معزولة بلا وصول للمضيف وبلا شبكة مفتوحة.
4. **التكلفة جزء من العقد:** كل تشغيل يسجّل توكنات/تكلفة ويوقف نفسه عند تجاوز الميزانية.
5. **الملكية على كل صف:** كل قراءة/كتابة/استئناف تتحقق من مالك الخيط، ولو كان المستخدم واحدًا اليوم.

## 4. المراحل ومعايير القبول

| المرحلة | المهمة | النطاق | معيار القبول (قابل للاختبار) |
|---|---|---|---|
| M1 — الذاكرة والحلقة | **AGENT-001** | `schema 2` + orchestrator + 3 أدوات قراءة، بث SSE، إلغاء، استئناف | مهمة واحدة تُنجز ≥3 خطوات وتُستأنف بعد إعادة تشغيل الخادم من آخر خطوة مؤكدة، دون تكرار أثر؛ طلب مكرر بنفس `client_message_id` لا يُضاعف؛ الحالة في MySQL لا في ذاكرة Node |
| M2 — الأثر الخارجي والموافقات | **AGENT-002** | outbox + approvals + أدوات كتابة (تقويم، إرسال WhatsApp، تصدير Drive) | كل أثر خارجي يمرّ بـ outbox وموافقة؛ انقطاع بعد الإرسال لا يُنتج إرسالًا ثانيًا؛ اختبار «موافقة مرفوضة» لا يترك أثرًا |
| M3 — العزل والمخرجات | **AGENT-003** | حاوة تنفيذ لكل مهمة + مخزن artifacts + تنزيل بانتهاء | كود يُنفَّذ داخل حاوية بلا وصول للمضيف/الشبكة إلا بقائمة سماح؛ ملف مخرج يُسلَّم برابط ينتهي؛ حدود CPU/ذاكرة/زمن مفروضة ومختبرة |
| M4 — منتج متعدد المستخدمين | **AGENT-004** | عزل مستخدمين، حصص، سياسة احتفاظ، تكلفة | مستخدم لا يرى خيطًا/ملفًا/تشغيلًا لغيره؛ تجاوز الحصة يوقف التشغيل برسالة واضحة؛ حذف حساب يحذف آثاره وفق DATA-004 |

M1 لا يحتاج أي حساب خارجي جديد ولا أسرارًا إضافية، ويمكن تنفيذه على بيئة التطوير الحالية. M3 لا يعمل على
طبقة استضافة مجانية بذاكرة صغيرة ونوم دوري — يحتاج قرار ميزانية من المالك.

## 5. حدود يجب قولها صريحة

- **التشغيل داخل آلة كاملة (كما يفعل Manus) ليس في المتناول** على Render Free: نوم، ذاكرة محدودة، بلا حاويات
  متداخلة. البديل الواقعي: عامل منفصل بحاوية واحدة لكل مهمة، أو تأجيل M3 مع إعلان التأجيل.
- **بايثون السبّابة منفصل بطبعه**: يعمل عبر stdio محليًا؛ ليكون أداة من أدوات الوكيل يلزم جسر (subprocess أو
  خدمة محلية) — عمل إضافي، لا مجرد تفعيل.
- **نطاقات Google الحساسة تحتاج تحققًا من Google** للاستخدام العام (وليس لحساب المالك وحده)، وموافقة OAuth
  تفاعلية لا تُنفَّذ داخل CI.
- **قانوني/خصوصية:** تنفيذ كود وأرشفة مخرجات لأشخاص آخرين يستلزم سياسة احتفاظ (DATA-004) قبل أي استخدام عام.
- **الادعاء محظور:** حتى إنجاز M1، هذه الوثيقة اتجاه لا قدرة.

## 6. القرارات المطلوبة من المالك قبل M1

1. **مستوى الاستقلالية الافتراضي:** موافقة على كل أثر خارجي (الأكثر أمانًا) أم موافقة مسبقة بنطاق؟
2. **أول عمودي (Vertical):** Google Workspace (بريد/تقويم/درايف) أم WhatsApp لخدمة العملاء أم مهام الملفات؟
3. **هدف البنية:** إبقاء الطبقة المجانية حتى نهاية M2 ثم قرار، أم ميزانية صغيرة لعامل تنفيذ من الآن؟
4. **تعدد المستخدمين:** مستخدم واحد (المالك) في M1–M2 مع تصميم يسمح بالتوسع، أم عزل كامل من البداية؟

الافتراض الموصى به إن لم يصل قرار: (1) موافقة لكل أثر خارجي، (2) Google Workspace أولًا، (3) مجاني حتى M2،
(4) مالك واحد الآن مع تحقق الملكية على كل صف.
