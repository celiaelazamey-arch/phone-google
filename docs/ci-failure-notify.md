# QA-009 — فشل `main` يفتح issue واحدة تسمّي الاختبار (DEC-041)

**التاريخ:** 29 أكتوبر 2026 · **الملفات:** `scripts/ci-failure-notify.mjs` · `.github/workflows/quality-failure-notify.yml` ·
`test/ci-failure-notify.test.js` (+ `test/fixtures/ci-failure-notify/red-run.json`) · **الصلاحية:** `GITHUB_TOKEN` فقط · **بلا نموذج لغوي، بلا تكلفة**

> الحلقة التي يغلقها: **يكتشف → يسمّي → يُبلّغ المالك**. وتتوقف هنا عمدًا: لا إعادة تشغيل، لا رقعة مولَّدة، لا rollback،
> لا دمج (DEC-039 رفض «إعادة التشغيل حتى الخضرة»؛ DEC-016 يجعل المخرج من الحالات المجهولة بشريًا). ما يُبلَّغ هو ما
> قالته annotations التشغيلة نفسها — وإن لم تقل إلا «Process completed with exit code 1» فهذا ما يُكتب، بلا تجميل.

## 1. ماذا يحدث فعلًا

| حدث على `main` | ما يفعله المُبلِّغ | ما لا يفعله |
|---|---|---|
| تشغيلة **Celia quality & resilience** تنتهي `failure`/`timed_out` (حدث `push`) | يقرأ وظائف التشغيلة عبر `actions/runs/{id}/jobs`، ثم annotations كل وظيفة فاشلة عبر `check-runs/{job}/annotations`، ويفتح **issue واحدة** بلصيقة `ci-failure` تحوي: اسم الاختبار، `الملف:السطر`، الوظيفة، رأس الخطأ (مُعقَّمًا)، سطر التغطية إن قصّر، السطر الختامي للمُبلِّغ، وأمر إعادة الإنتاج | لا يعيد التشغيل؛ لا يفتح issue ثانية (إن وُجدت مفتوحة يضيف **تعليقًا واحدًا لكل تشغيلة**، ومعرّف التشغيلة لا يُسجَّل مرتين) |
| التشغيلة التالية تنتهي `success` | يعلّق على الـissue المفتوحة ويغلقها | لا يُعيد فتح شيء؛ لا يكتب شيئًا إن لم توجد issue مفتوحة |
| تشغيلة `pull_request`، أو فرع آخر، أو `cancelled`، أو تجاوزتها تشغيلة أحدث مكتملة | `::notice` بسبب التخطي، خروج 0 | لا يلمس الـissues |

الوظيفة الفاشلة **بلا** annotation مسمّاة تُدرج صراحة تحت «Failed without a named test (open the job log)» مع رابط الوظيفة —
هذا هو الشكل الصادق لفشل البنية التحتية أو لوظيفة لا تمرّ بالمُبلِّغ.

## 2. من أين تأتي الأسماء

- `node --test`: المُبلِّغ `scripts/test-reporter-gha.mjs` (DEC-039) يبثّ `::error file=…,line=…,title=<اسم الاختبار>`، و`title=coverage threshold`
  لكل أرضية تغطية غير محققة، وسطرًا ختاميًا `title=node --test` بالأعداد وأسماء الفاشلين.
- المتصفح: مُبلِّغ Playwright المدمج `github` (`playwright.config.js`) يبثّ `::error file=…,line=…,title=<عنوان الاختبار الكامل>`.
- اختبار `test/ci-failure-notify.test.js` يربط المحلِّل بالباثّين نصيًا، فتغيير عنوان في المُبلِّغ يكسر الاختبار قبل أن يُصمت الإشعار.

## 3. الحوكمة والسلامة

| القاعدة | التنفيذ |
|---|---|
| أقل صلاحية | `permissions: contents: read · actions: read · checks: read · issues: write` — لا شيء غيرها (اختبار يثبت الكتلة حرفيًا) |
| لا أسرار | الاعتماد الوحيد `secrets.GITHUB_TOKEN`؛ لا يصل المُبلِّغ لأي سرّ من الـ18 |
| لا تسريب | كل نص منسوخ من annotation يمرّ بـ`redact()` (رموز GitHub/JWT/Bearer/`key=value`/hex طويل/رموز معتمة ≥40)؛ المسارات نسبية أصلًا؛ يُعرض `sha` قصير فقط |
| لا حلقات | الـissues المُنشأة بـ`GITHUB_TOKEN` لا تُطلق workflows أخرى (قاعدة GitHub) — فلا يراها الفرز المحكوم (AGENT-006) ولا تُعيد إطلاق نفسها |
| لا سباق | `concurrency: quality-failure-notify` بلا إلغاء؛ وتشغيلة تجاوزتها تشغيلة أحدث مكتملة تُتخطّى |
| لا تزوير للحالة | اللصيقة `ci-failure` + العلامة `<!-- qa-009 -->` + `<!-- qa-009 run:<id> -->` هي هوية الـissue؛ البحث بالعنوان مرفوض لأنه قابل للتغيير |
| لا «موكب» | لا يوجد ملف سجل محلي يُقرأ منه الفشل ولا `console.log` يدّعي الإرسال: كل كتابة أمر `gh` صريح مختبر ضد `gh` وهمي |

## 4. كيف تجرّبه

```bash
# قراءة حية لأي تشغيلة (لا يكتب شيئًا): تشغيلة main الخضراء بعد دمج PR #72
GH_TOKEN=$(gh auth token) npm run ci:notify -- --run 40797023396 --dry-run
# المسار الأحمر كاملًا على fixture بشكل الـAPI الحقيقي (اسمان، تغطية، وظيفة صامتة، سرّ مُعقَّم)
npm run ci:notify -- --run 41000000001 --fixture test/fixtures/ci-failure-notify/red-run.json --dry-run
# من Actions: workflow_dispatch «Quality failure notify (main)» بمعرّف تشغيلة؛ dry_run = true افتراضيًا
```

## 5. الحدود (ما لا يُدّعى)

- `workflow_run` لا يعمل إلا من نسخة الملف على **الفرع الافتراضي**؛ لذلك **الدليل الحي الأول يظهر بعد الدمج في `main`** عند أول
  تشغيلة Quality مكتملة — وحتى ذلك الحين حالة QA-009 في BACKLOG «بانتظار» لا «متحقق».
- GitHub يعرض ≤10 annotations لكل مستوى لكل خطوة، لكن الـAPI يُرجع ما بُثّ كله؛ المُبلِّغ يبثّ 9 تفصيلية + ختامية تحوي الأسماء،
  فالأسماء بعد التاسع تأتي من السطر الختامي لا من صفوف الجدول.
- لا يفتح الإشعار على تشغيلات `pull_request` ولا على فروع العمل: الفروع تكفيها annotations التشغيلة نفسها.
- بريد GitHub عن فشل الـworkflow يذهب لمن دفع الـcommit؛ الـissue هي القناة التي تصل المالك مهما كان الدافع (نفس منطق DEC-031).
