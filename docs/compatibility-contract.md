# عقد التوافق وعدم التعارض

**التاريخ:** 27 أكتوبر 2026 · **المرجع:** سيليا `0.2.0` عند `6f1dbb3`.

هذه سياسة تصميم ومراجعة واختبار للتغييرات القادمة، وليست ادعاءً بأن اختبارات التوافق الجديدة منفذة الآن. تفاصيل التنفيذ في [BACKLOG](continuity/BACKLOG.md)، والاتجاه العام في [خطة 2026](2026-development-plan.md).

## 1. حدود المسؤولية

- نحافظ على السلوك المثبت ما لم يعتمد المالك تغييرًا صريحًا له.
- لا يوجد «ضمان عدم تعارض» دون معرفة بيئة المستخدم وتجربة التغيير عليها في staging معزول.
- غياب معلومة لا يبرر اختيار قيمة أو استضافة أو مخطط بديل تلقائيًا.
- الوثائق فقط لا تغيّر النظام؛ اعتماد الخطة لا يعني الموافقة على الترحيل أو النشر أو التكلفة أو توسيع الصلاحيات.

## تحديث التنفيذ 0.2.1 — دون تغيير schema

[دليل النشر](free-hosting.md) يصف الخيار الجديد لا افتراضًا عن نظام قائم. `CELIA_ENABLE_INTEGRATIONS` معطل افتراضيًا؛ يفعّل المسارات الأصلية نفسها على منفذ MCP ويطبق PORT المضيف عند تفعيله فقط. `.env` القديم يبقي فصل PORT لخادم REST وCELIA_MCP_PORT لخادم MCP. لا تغيير لأدوات MCP الاثنتي عشرة أو SQL أو آلية منع إعادة الأفعال.

تهيئة `empty-only` صريحة لأول قاعدة فارغة تمامًا (حتى وجود views يمنع اعتبارها فارغة)، وليست ترحيلًا عند startup. قواعد قائمة غير متوافقة تُرفض دون repair. فحص الأعمدة ليس تدقيقًا كاملًا للقيود والفهارس؛ لا يبرر الادعاء بتوافق إنتاج مجهول.

اختبار N/N−1 الجديد محدود حاليًا بأدوات MCP وقراءة schema1 في بيئة MySQL8.4 مصطنعة مع dump/restore مستقل؛ ليس corpus كاملًا لكل عميل/مزوّد. اختبار0.2.0 يتم على SQL محلية معزولة، لا شهادة اتصال Aiven/TLS؛ لا يعرف متغير CA الجديد وقد لا يتصل بقاعدة المزوّد بعد الرجوع. 0.2.0 لا يعرف تجميع REST، لذلك لا يعد الرجوع إليه استمرارًا لكل المسارات الجديدة. تبقى بوابات الترحيل ونسخة الحساب الفعلية المستعادة واجبة قبل بيانات الإنتاج أو مخطط جديد.

## إضافة الجلسة الحالية — جداول وكيل إضافية بسجل ترحيل مستقل

`0.2.1` يحتفظ بـ`database.schema = 1` وبالجداول الخمسة الأصلية دون أي تعديل. الجداول `agent_*`
(`agent_threads`/`agent_messages`/`agent_runs`/`agent_steps`/`agent_tool_runs`) **إضافية تمامًا**، ولا تُنشأ إلا بأمر
مالك صريح `npm run migrate -- --apply` عبر سجل `schema_migrations` ببصمات SHA-256؛ لا إنشاء تلقائي عند startup،
ولا ALTER/DROP لأي جدول قائم، ولا تغيير لعقد `validateProbe` (`db.schema` يبقى 1).

- الحلقة اختيارية ومعطلة افتراضيًا؛ غياب الجداول يعطي `503 agent_schema_missing` مع الأمر المطلوب، لا ارتدادًا صامتًا.
- الرجوع إلى صورة لا تعرف `/api/agent` لا يفقد بيانات الخمسة جداول؛ يترك جداول `agent_*` بلا استخدام.
- **غير متحقق:** تطبيق الترحيل على MySQL حي، وأي صورة منشورة. وصف SQL بأنه إضافي لا يُغني عن اختبار CI.

## 2. مصفوفة العقود التي يجب تثبيتها قبل التنفيذ

| السطح | ما نحافظ عليه | فحص القبول المطلوب |
|---|---|---|
| HTTP العام | liveness/readiness/version، تنقيح الحالة العامة، التمييز بين unavailable وunconfigured | fixtures للحالة/JSON، فشل DB مع استمرار liveness؛ لا إخراج أسرار |
| REST للمالك | المسارات وطرق HTTP الحالية وBearer وسياسة الأخطاء والموافقة | اختبارات الطلبات الحالية + رفض غياب/خطأ الرمز والمدخلات غير المصرح بها |
| Google OAuth | state أحادي الاستخدام ومهلة/cookie وربط حساب المالك والنطاقات | callback مطابق لعنوان البيئة؛ منع replay وتغير الحساب؛ لا توسيع scopes صامت |
| WhatsApp | HMAC على raw bytes، dedup، الموافقة المسجلة وموافقة AI ونافذة الخدمة | توقيع خاطئ وتكرار ووصول متزامن ورفض الإرسال دون الشروط؛ لا بث جماعي |
| MCP القديم | 12 أداة وأسماؤها ومدخلاتها، HTTP وstdio، العملاء الحاليون | corpus من initialize/tools/resources/prompts/errors ومصفوفة عميل/نسخة |
| MCP الحديث | مسار/محول صريح وتحقق من إصدار وقدرات كل طلب حسب المواصفة المستهدفة | server/discover و_meta وresultType وheaders/schema وHTTP/stdio؛ لا كسر legacy |
| الواجهة | `/studio` و`/landing` و`/live` و`/skills` و`/system` وخيار root الحالي | هاتف/حاسوب، RTL، تنقل ولوحة مفاتيح، أصول محلية وCSP |
| Pages | مسار المستودع الفرعي وdemo الصريح، بلا أسرار خادم أو نجاح إرسال وهمي | اختبار subpath وروابط وأصول وغياب صلاحيات/اتصال إنتاج غير مصرح به |
| إعدادات البيئة | أسماء المتغيرات ومعناها وصرامة التحقق وخيارات تعطيل المزوّدين | تشغيل بالتكوين القديم دون تغيير؛ ميزات إضافية معطلة افتراضيًا |
| MySQL | البيانات الحالية والقيود والفهارس والتشفير والملكية؛ لا ذاكرة بديلة | نسخة مماثلة منقحة واختبارات SQL حقيقية وN/N−1 وترحيل قابل للإيقاف |
| مزوّدو AI | auto المحكوم والاختيار الصريح؛ لا تسريب لمالك المعاينة أو مزوّد غير مسموح | فشل/429/مهلة، رفض الموافقة الناقصة، لا مفاتيح في السجلات أو المتصفح الإنتاجي |
| النشر | digest/version/schema وحالة active/previous/pending وحدود MCP الحالية | فحص مرشح وفشل تفعيل/حفظ/رجوع/انقطاع، مع بقاء journal عند تعذر الاستعادة |

اختبارات N/N−1 هنا مطلب جديد. اختبارات الإصدار الحالية لا تثبت وحدها أن كل تغيير مستقبلي متوافق.

## 3. ما نسجله في جرد بيئة المستخدم — دون أسرار

- خدمة الاستضافة والمنطقة ونظام التشغيل وطريقة التشغيل، ونسخ Node وDocker/Compose وMySQL.
- خادم MCP وخادم OAuth/Webhook: أيهما يعمل وأين، عنوان HTTPS العام ومسارات proxy وOAuth callback وأسماء المنافذ لا رموز الوصول.
- نسخة/اسم عميل MCP ونمط HTTP أو stdio، والتخصيصات المحلية غير الموجودة في المستودع.
- نسخة schema الفعلية والجداول/القيود/الفهارس والحجم التقريبي؛ لا نسخ صفوف عملاء إلى Git.
- أسماء متغيرات البيئة المطلوبة فقط وموضع مخزن الأسرار وآلية التدوير، لا القيم أو الملف الكامل.
- سياسة النسخ والاحتفاظ ونتيجة آخر restore ومَن يملك قرار النشر والرجوع.
- الحمل المقبول والميزانية وحدود الانقطاع ومكان البيانات ومتطلبات الموافقات/الحذف.

لا تجمع `env` كاملًا أو `docker inspect` كاملًا في تقرير عام؛ قد يحتويان كلمات مرور وتوكنات. تُراجع مخرجات الجرد وتُنقّح قبل الحفظ.

## 4. ترحيل البيانات دون كسر الرجوع

1. نسخة مستقلة مشفرة واختبار restore إلى قاعدة أخرى قبل لمس الإنتاج.
2. توثيق الفرق، والترحيل الإضافي وأداة تسجيل تنفيذه ومعاملته وسلوك الانقطاع؛ لا تشغيل ترحيل تلقائي مع كل startup.
3. مراجعة `validateProbe` والعقد الحالي: يتطلب تطابق schema ونطاق القراءة و`destructiveMigration=false`. لا يكفي وصف SQL بأنه additive ليمر.
4. إن احتاج التغيير schema جديدًا، نصمم إصدار جسر وآلية انتقال واختبارات قبول القديم للتركيب الجديد. لا نزيد `maxReadable` أو نتجاوز البوابة دون تنفيذ اختبار فعلي.
5. expand ثم backfill قابل للاستئناف ثم switch خلف خيار جديد. تبقى القراءة القديمة متاحة ما دام الرجوع مطلوبًا.
6. اختبار قطع الترحيل والتكرار وتنافس العاملين والقراءة بالنسختين. العمليات الخارجية لا تُعاد ضمن backfill.
7. contract/حذف الأعمدة القديمة عملية لاحقة بعد انقضاء نافذة الرجوع وموافقة مستقلة ونسخة جديدة مستعادة؛ لا تدخل ضمن هذا البرنامج تلقائيًا.
8. فشل التوافق يوقف الترقية؛ استعادة البيانات إجراء منفصل، ولا يُوصف rollback للكود بأنه restore.

## 5. تغييرات البروتوكول والذاكرة

MCP `2026-07-28` يزيل handshake وجلسات النقل القديمة، لذلك لا نحاول تخزين سياق المستخدم داخل حالة اتصال MCP أو افتراض أن `Mcp-Session-Id` عقد دائم.

- تبقى المحادثات والمهام في مخزن التطبيق ومعرفات مصرح بها؛ ليس في اتصال النقل.
- يتحقق محول legacy من الرسائل القديمة، ومحول 2026 من متطلبات الإصدار الجديد. موقع نقطة النهاية وآلية اختيار المحول يُعتمدان بقرار قبل التنفيذ، ولا يُفترضان كمنفذين الآن.
- لا توسيع capabilities أو إعلان extension غير منفذ ومختبر.
- تختلف إعادة محاولة طلب نقل عن إعادة تنفيذ الفعل: معرف عملية دائم وidempotency يمنعان مضاعفة نية الإرسال، وتبقى النتيجة المجهولة بلا retry أعمى.
- cacheScope والـheaders وسياق trace تُنقّح وتُختبر حتى لا تنتقل بيانات مالك إلى cache عام.

## 6. بوابة قبول كل PR تنفيذي

- [ ] معرف مهمة ومطلب واضحان؛ لا إعادة كتابة شاملة أو تعديل جانبي بلا سبب.
- [ ] مقارنة العقود المتأثرة وبيان ما بقي كما هو وما يتغير.
- [ ] مدخلات الجرد اللازمة معروفة، وبيانات الاختبار مصطنعة.
- [ ] التكوين القديم يعمل والميزة الجديدة اختيارية؛ لا حذف سر/اسم متغير أو توسيع scope صامت.
- [ ] اختبارات مناسبة ناجحة على commit التغيير، لا مجرد نتيجة من جلسة سابقة.
- [ ] إن مس التغيير بيانات: SQL حقيقي وrestore وN/N−1 وإصدار جسر عند الحاجة.
- [ ] إن مس أفعالًا خارجية: موافقة وصلاحية وidempotency وunknown ومصالحة.
- [ ] تحديث دليل التشغيل والخطة/الحالة/القرار حسب الأثر، ولا أوامر مستقبلية تُعرض كمتاحة الآن.
- [ ] خطة تعطيل/رجوع وحدودها، ومنفذ القرار ومراقبة ما بعد النشر محددون.
- [ ] موافقة منفصلة قبل إنتاج أو تغيير بنية أو كلفة أو سياسة مشاركة.

## 7. متى نتوقف؟

عند فشل اختبار، أو غياب قاعدة مستعادة، أو وجود تغييرات مستخدم غير مفهومة، أو schema مجهول، أو عميل لا يستطيع الاستمرار، أو قرار تكلفة/خصوصية غير معتمد. نسجل العائق والخطوة الآمنة في STATE ولا نحذف البيانات أو الـjournal أو نتجاوز المصادقة لحلّه.

المرجع للأوامر المنفذة حاليًا: [دليل الإصدارات](releases-and-recovery.md) و[حدود العزل](resilience.md).
