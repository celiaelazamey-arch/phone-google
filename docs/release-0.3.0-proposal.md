# قرار الإصدار `0.3.0` — جرد ما دخل الإنتاج بعد `v0.2.1` ونتيجة الترقية (`REL-003`)

**الحالة:** اعتمد المالك `0.3.0` في 2 نوفمبر 2026 (REL-003 / DEC-113)، ودُمج PR #136 ونُشر الإصدار immutable عند `7596c27e3d34e7eb452a9f5accf41415bd30c714`. قبول Edge الحيّ وقراءة D1 الراجعة ناجحان. Pages نجح في فحص 13/13 مسارًا من SHA نفسه؛ لكنه لم يقرأ جسم `version.json` الحي مباشرة، لذلك هذا الإثبات المحدد باقٍ قبل إغلاق REL-003. يبقى `v0.2.1` مجمّدًا كما هو.

## ٢. لماذا `0.3.0` (Minor) لا `0.2.2` ولا `1.0.0`؟

1. **ليست `0.2.2` (Patch):** ما دخل `main` ليس إصلاحات معزولة، بل قدرات معمارية كاملة لم تكن في `0.2.1` (حسابات واتساب ذاتية الخدمة بعزل مستأجرين، مصفوفة الصلاحيات 67 منحة، ذاكرة الوكيل الدائمة، طابور الانتباه والتفويض المقيّد، حارس التقدّم الصفري، بوابة وسجل النشر بسلسلة هاش، هجرة الألوان الكاملة، وشرائح النشر المثبتة بـOIDC).
2. **لا كسر توافق عكسي:** جميع مسارات وأدوات MCP الـ12 وعقود `compatibility-contract.md` محفوظة؛ وهجرات قواعد البيانات (`sql/migrations/0002..0008` و`workers/celia-edge/migrations/0001..0008`) إضافية بحتة (`CREATE TABLE IF NOT EXISTS`، صفر `DROP`/`ALTER`، `destructiveMigration: false`، `schema: 1`).
3. **ليست `1.0.0`:** لأن فجوات وحدودًا صريحة ما زالت مفتوحة ومعلَنة بقرار:
   - `SEC-007` فجوة أمنية مخططة لم تُغلق بعد.
   - `conflict_resolution` غائبة في أطلس النظام (`multi_agent` عند 75٪).
   - ربط واتساب الذاتي **موجود برمجيًا ومنشور على الطرفية** لكنه **غير مفعَّل تشغيليًا** (`configured: false` بانتظار أربعة إعدادات Meta من المشغّل).
   - خادم Render الكامل غير مفعَّل (`not-configured` بانتظار مفاتيح Render).

### ما دخل `main` وما يضيفه طلب الإصدار
- **PR #123** دُمج في `2026-11-01T11:14:03Z` عند `c5fe0a854801aafc8f302bda2c516417502fdcdd`: ناقل التعاون `XAG-001`، وقياس التوازي، وتحسينات أنبوب CD. كان قيده مفقودًا؛ أُضيفت مصالحة append-only في `seq=5` ببصمة `pub:7e2e7a88e09a45ef` من مصدرها، دون إعادة كتابة أي قيد سابق. `npm run publish:ledger:verify` يثبت 8 قيود وسلسلة سليمة.
- **PR #130** و**PR #135** سبقَا هذا الإصدار؛ كان `main@3aa4024` خط الأساس قبل PR #136.
- **PR #136** دُمج بـsquash في `7596c27…` وزامن الإصدار والاختبارات والـmanifest؛ لم يغيّر وحدات Worker runtime. بعد ذلك نُشر `v0.3.0` وقُبل Edge+D1 على SHA الدمج نفسه؛ أدلة التشغيل والبصمات في [سجل النشر](deployments/ledger.json).

## ٤. القرار المعتمد — `REL-003`

- **اعتماد المالك:** اختيار `0.3.0` Minor وفق المسودة، في 2026-11-02. وُحّدت ملفات الإصدار `package.json` و`package-lock.json` و`releases/current.json` و`releases/history.json` و`system.manifest.json`، ونُقلت بنود `Unreleased` إلى `0.3.0` في `CHANGELOG.md`؛ لا يصبح الإصدار منشورًا إلا بعد نجاح بوابات النشر.
- **حماية الإصدار السابق:** يظل `v0.2.1` كما هو (`immutable: true`)؛ لا `--clobber` ولا تغيير لمحتواه. النشر ينشئ وسم `v0.3.0` جديدًا فقط إذا نجحت بوابات الإصدار.
- **شروط الإصدار التي اجتازت التشغيل:** `release:check` وCI/CodeQL، التحقق من الأصول/الشهادة، نشر Pages وCloudflare Edge+D1 للالتزام نفسه، وقراءة D1 الراجعة قبل `known_good`. بوابتا `release` و`production-edge` نجحتا عبر المسارات القائمة دون bypass. التفاصيل في تشغيلات `41399947570`, `41399947941`, `41400115739`.
- **حدّ دليل Pages:** التحقق الحي أعاد 13/13 مسارًا HTTP 200، والبناء أنشأ `version.json` من `RELEASE` و`GITHUB_SHA` الخاصين بالتشغيل؛ لكن الـprobe لم يقرأ جسم JSON، لذلك يظل فحص المحتوى المباشر مطلوبًا قبل إعلان استيفاء حرفي لكل REL-003.
- **حدود صريحة:** هذا الإصدار لا يدّعي خادم Render أو ربط Google/WhatsApp. Render run `41400115801` أعلن `not-configured` ولا URL، Google غير مربوط، وWhatsApp `configured=false` لنقص إعدادات Meta ومفتاح التشفير.

## ٥. خطة التراجع المعتمدة بعد الترقية

1. **الطرفية (`Cloudflare Edge`):** التراجع إلى آخر شريحة `known_good` مثبتة في جدول `edge_deployment_slices` أو عبر `git revert` لالتزام الدمج؛ الجداول الجديدة إضافية بحتة فلا هجرة عكسية ولا فقد بيانات.
2. **الموقع الثابت (`GitHub Pages`):** تشغيل `pages.yml` يدويًا بمدخل `release_tag: v0.2.1` ليستعيد الحزمة الموقّعة بعد التحقق من شهادة OIDC.
3. **حزم الإصدار وصور الحاويات:** `v0.2.1` مجمّد (`immutable: true`)، وفحص التجميد المبكر في `release.yml` يمنع المساس بوسم صورته.
