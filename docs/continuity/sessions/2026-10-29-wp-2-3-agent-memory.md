## 2. التنفيذ

1. **المخطط:** `sql/migrations/0005_agent-memory.sql` يضيف `agent_thread_summaries` و`agent_owner_facts` بأعمدة الملكية والمصدر والإنشاء والتحديث والانتهاء، مع قيد ملخص واحد لكل خيط وقيد `(owner_id, tag)` للحقائق. أُضيف DDL المكافئ وفحص الجداول إلى SQLite؛ MySQL يبقى عبر سجل الترحيل الصريح، وقبوله يتوقع أربع ملفات و11 جدول `agent_`.
2. **الاشتقاق:** `src/agent/memory.js` دالة نقية ترتب الخطوات وتشتق الحالة وعددها وأسماء أدوات `act` وآخر نص `deliver` آمن. تستعمل `findSecret` من `src/knowledge/validate.js`؛ النص المشتبه به لا يدخل الملخص أو الحقائق، ولا تُنسخ رسائل المستخدم أو حمولات الأدوات الخام.
3. **المخزن:** upsert للملخص والحقيقة مع الاحتفاظ بـ`created_at`، قراءة قوائم/عناصر بملكية، إخفاء المنتهي افتراضيًا، والتحقق من أن `source_run_id` يعود للمالك والخيط نفسيهما. `deleteMemory` ينفذ `DELETE` ويلحق `memory_deleted` في معاملة واحدة، عبر مساعد الأدلة المشترك نفسه وسلسلة SHA-256 للتشغيل المصدر.
4. **الحلقة:** `finish()` يحدّث الذاكرة قبل بث `run.finished`؛ سياق المخطط يحمل `memory` و`context_memory: {summaries:true,facts:true}`، ومكوّن `context_memory` في الـharness يعلن القدرتين.
5. **HTTP والواجهة:** `GET /api/agent/memory` للقوائم أو عنصر مفرد بـ`kind/id`، و`DELETE /api/agent/memory` بجسم أو استعلام؛ كلاهما خلف `authorize`. قسم «ما يتذكره الوكيل» يعرض الملخصات والحقائق ومصدرها ويتيح «حذف نهائي» ثم يعيد القراءة من الخادم.
