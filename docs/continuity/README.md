# الاستمرارية بين الجلسات — دليل الاستئناف والتسليم

هذه ذاكرة **عمل المشروع** المحفوظة مع الكود. ليست قاعدة محادثات العملاء، ولا مكانًا للأسرار أو بيانات الإنتاج. خطة ذاكرة التطبيق الدائمة في [خطة 2026](../2026-development-plan.md) ومهام DATA في BACKLOG.

التقارير القديمة تبقى محفوظة وموسومة تاريخيًا. نسخة Google Docs أو رسالة دردشة لا تصبح مرجع حالة ثانيًا؛ عند تصدير تقرير لاحق يُكتب تاريخه وcommit ورابط المرجع، ولا تُنقل أسرار أو سجلات عملاء إليه.

## بداية كل جلسة — قبل أي تعديل

```sh
pwd
git branch --show-current
git status --short
git log -5 --oneline
```

1. اقرأ [AGENTS.md](../../AGENTS.md)، ثم STATE وBACKLOG وDECISIONS وهذا الدليل.
2. استخدم فرع البيئة النشط، حتى لو ورد اسم فرع آخر في آخر تقرير. لا تنشئ أو تنتقل إلى فرع بديل في بيئة تربط الجلسة بفرع ثابت.
3. احترم تغييرات المستخدم غير المحفوظة؛ لا تعمل `reset --hard` أو `clean` أو تزيل ملفات لتبدأ من «حالة نظيفة».
4. راجع حقائق المصدر المطلوبة للمهمة. إذا كان الادعاء عن PR/CI/نشر، افحصه مباشرة بقراءة GitHub؛ لا تنفذ نشرًا لفحص ما إذا كان قد نُشر.
5. اختر معرف مهمة ومعيار قبول، وسجل أي فرق عن STATE قبل تغيير الكود. إن كانت هناك مهمة جارية أو `pending` نشر، افهمها أولًا.

## أثناء الجلسة

- كل مطلب مهم جديد يأخذ معرفًا أو يدخل قرارًا؛ لا يبقى حصريًا في الدردشة.
- حدّث نقطة الاستئناف عند تغيير المهمة أو اتخاذ قرار أو اكتشاف عائق، لا في نهاية طويلة فقط.
- checkpoints للعمل تحفظ بتغييرات صغيرة مفهومة وcommit مناسب عندما يكون ذلك مسموحًا. لا تستخدم ميزة الحفظ كذريعة لإيداع أسرار أو artifacts ضخمة.
- سجّل أمر الاختبار والنتيجة والتاريخ/commit وسبب أي تجاوز. عدم التنفيذ ليس نجاحًا، وغياب إعداد تكامل ليس اتصالًا صحيًا.
- لا تنسخ أرقام الاختبارات أو حالات المهام إلى تقارير متعددة غير قابلة للتحديث؛ ارجع إلى المصدر المختص.

## نهاية كل جلسة أو قبل توقف طويل

1. حدّث STATE: ما تغير، ما ثبت، ما لم يُثبت، العوائق، ومعرف الخطوة التالية.
2. حدّث صفوف BACKLOG المتأثرة فقط. لا تغلق مهمة تنفيذية لأن خطة لها كُتبت.
3. أضف قرارًا إذا تغيرت البنية أو الحدود أو التفويض، وسجل جلسة من [القالب](SESSION_TEMPLATE.md) باسم فريد مؤرخ تحت `sessions/`.
4. راجع `git diff --check` ونطاق التغيير والأسرار والملفات المتولدة. نفذ الفحوص المناسبة للأثر الفعلي.
5. احفظ التغييرات. عند تفويض الدفع، ادفع **فرع البيئة فقط** وافتح PR؛ لا تدمج أو تنشر أو تغير حماية الفرع دون طلب.
6. سجل رابط التسليم. إن تعذر الدفع أو تعذر التحقق من CI، اكتب «غير متحقق» وسبب العائق، ولا تصفه بأنه تم.

## التعافي إذا انقطعت الجلسة قبل التسليم

- افحص worktree وGit وآخر سجل جلسة؛ قد تكون تغييرات غير committed موجودة بالفعل. لا تستبدلها بخطة قديمة.
- قارن الملفات بـSTATE والمهام، وأعد الفحوص اللازمة. لا تعتمد على سجل جزئي كإثبات إتمام.
- إذا كانت عملية خارجية قد بدأت ولا نعرف نتيجتها، لا تعد إرسالها. ابحث عن سجل العملية/معرف المزوّد أو اطلب مراجعة المشغّل.
- عند نشر منقطع، اتبع runbook و`pending`/القفل و`recover`؛ لا تمسح الحالة أو الأحجام للبدء من جديد.
- إذا غاب أي سياق، سجّل «مجهول» وخطوة تحقق آمنة بدل اختلاق تاريخ أو قرار.

## ما لا تضمنه هذه الآلية

لا تُلزم خدمة محادثة خارجية بالاحتفاظ بكل النص، ولا تنسخ بيانات MySQL، ولا تمنع فقد جهازين معًا من دون نسخة بعيدة. قيمة الآلية في وجود سياق قابل للفحص والاستئناف داخل Git؛ فاحص CONT-003 البنيوي وبوابة handoff في PR موجودان الآن، لكنهما لا يضمنان صدق كل معلومة أو توافق كل عميل. تظل تغطية COMP-002 الشاملة عملًا مستقلًا.

## الفاحص المنفذ

```sh
npm run now:check
npm run check:continuity
# في PR CI: مرجع base SHA ثابت، لا اسم فرع متغير:
CELIA_CONTINUITY_BASE=<40-character-commit-sha> npm run check:continuity
```

يفحص الروابط المحلية والمهام الفريدة والأولوية/فئة الحالة وتبعياتها والدورات ومطابقة `NOW.md` المشتق لمصادره بايتًا ببايت. عند تحديد base، يلزم STATE وسجل جلسة إذا مس فرق commits التنفيذ. لا يقرأ أسرارًا، ولا يشغّل تطبيقًا/نشرًا، ولا يساوي صحة الربط صحة الادعاءات البشرية. لا يوضع `<...>` حرفيًا كمرجع Git.
