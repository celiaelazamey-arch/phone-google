## المنفذ الآن

1. **تشغيل اختياري موحّد:** `CELIA_ENABLE_INTEGRATIONS=true` يعيد استخدام مسارات Google وWhatsApp الأصلية على منفذ MCP نفسه، مع Bearer/HMAC raw-body والموافقات والعزل. الوضع الافتراضي MCP القديم و`npm start` مستقلان كما كانا. PORT الخاص بالاستضافة يطبق في الوضع الموحد فقط حتى لا يكسر `.env` القديم.
2. **MySQL إنتاجية موثّقة TLS/CA واسم المضيف** مشتركة للتحميل، ولا تعطيل تحقق أو fallback ذاكرة عند الفشل.
3. **تهيئة صريحة empty-only** لأول قاعدة فارغة فقط، بقفل وفحص الأعمدة ورفض غير المتوافق دون DROP/ALTER. ليست migration ولا شهادة تدقيق schema كامل.
4. **مركز نشر عربي `/deploy`** و`/api/deployment` منقحان، حالة live/blocked/stale وتنزيل JSON؛ Pages يعلن تجربة المتصفح صراحة. لا جمع أسرار ولا تعديل تشغيل من الواجهة.
5. **Blueprint مجاني واحد** في `render.yaml`، توليد مفاتيح ومداخل DB في Dashboard، ونشر تلقائي معطل. المسار التجريبي السابق محفوظ في `render.demo.yaml`.
6. **اختبارات MySQL8.4 جديدة في CI** للتهيئة والمعاملات والتكرار المتزامن وإعادة التشغيل وتوافق MCP0.2.0 وdump/restore في قواعد مصطنعة منفصلة. وجود الحزمة ليس نجاح تنفيذها؛ انظر CI الحي/سجل الجلسة.
7. **فاحص استمرارية** `npm run check:continuity` للروابط والمهام والحالات البنيوية والدورات؛ مع `CELIA_CONTINUITY_BASE=<immutable SHA>` يلزم STATE وسجل جلسة عند تغيير التنفيذ. PR CI يفعّل بوابة نطاق التغيير. لا يُصادق على صدق كل عبارة بشرية.

## حدود لا يجوز نسيانها

- `allCapabilitiesVerified=false` مقصود دائمًا في endpoint القراءة؛ فهو لا يجمع قبولًا خارجيًا. عنوان يقدمه المزوّد أو مفاتيح مُهيأة لا يساوي اتصالًا أو نشرًا متحققًا.
- لا ذاكرة محادثات عامة دائمة، outbox، محول MCP2026، Node26 مختبر، HA أو استعادة إنتاج مثبتة بعد. تبقى مهام الخطة.
- CI أثبت قراءة0.2.0 لـschema1 في SQL محلية معزولة، لا نشره على Aiven. لا يعرف متغير CA الجديد أو تجميع REST؛ قد يفشل TLS عند الرجوع على مزوّد خاص CA، لا تعد بعودة كل المسارات الجديدة على نفس المنفذ بعد ذلك. أول نشر لا يختلق صورة سابقة سليمة.
- الطبقات المجانية تنام ومحدودة الموارد؛ لا ضمان uptime أو تجاوز تحقق دفع. إذا طلب مزوّد بطاقة نتوقف وفق شرط المستخدم.
- لا بيانات إنتاج أو مشاركة سحابية أو إعداد OAuth/Meta فعلي أو شراء أو إدخال بطاقة أو migration لقاعدة قائمة ضمن هذا التنفيذ.

## الخطوة التالية بالضبط

**HOST-003 — تفويض حسابات الاستضافة دون أسرار في الدردشة.** المالك يسجل الدخول إلى Aiven/Render ويختار Free ويضع إعدادات DB في Dashboard من [الدليل](../free-hosting.md). زر `/deploy` يفتح الفرع المصدر الصحيح عند المعاينة.

بعد توفر **رابط الخدمة الفعلي**: تحقق خارجيًا من HTTPS وSHA وreadiness والتخزين، ثم إعادة التشغيل، ثم OAuth/Webhook الفعلي بعد موافقات المالك. أكمل جرد البيانات/المفاتيح والنسخ والاستعادة COMP-001/DATA-001 قبل أي ترحيل أو DATA-002/DATA-003. لا تكرر محاولة Pages403 أو تبحث عن أسرار شخصية لتجاوز عائق التفويض.
