## 2. ما نُفِّذ في هذا الفرع (قابل للإثبات هنا، بلا حساب خارجي)

1. **الاستعادة عند الإقلاع (DEC-018):** `runtime.recoverOnBoot()` = `outbox.recoverStale()` ثم `resumePending()`؛
   `agentHost.recoverOnBoot()` لا يرمي أبدًا ويسجّل النتيجة في `status().bootRecovery`؛ `scheduleBootRecovery()`
   موصولة بـ`src/celia-mcp.js` و`src/server.js` بعد `listen`. **افتراضيًا معطّلة** (`CELIA_AGENT_RESUME_ON_BOOT=false`)
   فلا يتغيّر سلوك قائم بصمت. اختبار يثبت: نية `dispatching` مهجورة تصير `unknown` **بلا استدعاء موصل**، تشغيل
   `queued` يكتمل، تشغيل باستدعاء غير محسوم يركن في `needs_reconciliation`، والإقلاع الثاني لا يغيّر شيئًا.
2. **القبول التنفيذي:** `scripts/verify-live.mjs` (`npm run verify:live`) — سبعة فحوص آلية (رابط https، وصول،
   زمن إيقاظ، `/version` مع commit، `/readyz` بـMySQL دائمة، بوابة 401، `/api/agent/status` بالرمز من البيئة
   فقط) + أربعة بنود `manual` معلنة. يرفض كتابة تقرير يحوي الرمز، ويسجّل المضيف فقط. اختبار سلبي: التطبيق
   الحقيقي على ذاكرة صريحة **يفشل** الفحص؛ اختبار إيجابي: خدمة مثالية تنجح؛ عدم تطابق commit إخفاق.
3. **تحديث الخطة والعقد:** `deploy/free-always-on/README.md` (حالة Pages الجديدة، المتغيّر الجديد، §5 بالأمر)،
   و`test/free-hosting-plan.test.js` يسمح بالمتغيّر الاختياري الجديد دون إضافته إلى `render.yaml`.

**لم يُنفَّذ ولم يُدَّع:** لا نشر، لا حساب، لا ترحيل على قاعدة حقيقية، لا تغيير في `render.yaml` أو `schema 1`
أو الإصدار أو أدوات MCP، لا دمج ولا إغلاق PR، لا نداء دوري مُنشأ.
