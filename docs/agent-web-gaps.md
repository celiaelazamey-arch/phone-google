# خطة إغلاق الفجوات — الوصول إلى الويب والأدلة (نقد بناء + ربط الشبكة الداخلية)

> **الحالة:** وثيقة تخطيط فقط — **لا كود جديد فيها**. مبنية على ما هو **مدموج فعلًا** في `main@e99ebaf` (C1-a، C1-b، C2-a أداةً وحلقةً، DEC-059/060/061/062).
> **آخر تحديث:** 2026-10-29 · **الفرع:** `arena/afe3493a-phone-google`
> **قاعدة الصدق:** كل «مُثبت» هنا مقيس في المستودع (اختبار أو بوابة)، وكل «غير مُثبت» مذكور بصراحة. لا يُقرأ شيء هنا كإثبات عمل الإنترنت العام.

## 1. أين نقف بالضبط

| مُثبت بالقياس | غير مُثبت |
|---|---|
| منحة واحدة لكل جلب، تُسحب في `finally` — `activeGrants()` فاضية بين الخطوات | أي اتصال بإنترنت حقيقي (كل المشاهد على `127.0.0.1`) |
| قرار قائمة قبل أي اتصال، وتُعاد عند كل redirect | `CELIA_AGENT_EGRESS=proxy` مُفعَّلًا في أي بيئة |
| ٣ مصادر → ٣ صفوف أدلة، وكل سطر ملخّص يحمل URL وبصمة | بحث عن مصادر لم يقدّمها المستخدم (`web.search`) |
| رفض صريح بلا تفعيل، وتوقف مسمّى عند فشل مصدر أو نفاد ميزانية | تلخيص دلالي بنموذج (الملخّص **مقتطفات منسوبة**) |
| حقن يُنقّى قبل القراءة، ولا قدرة إضافية تُمنح | ربط بالشبكة الداخلية (خدمات، مصادقة، تصنيف بيانات) |
| سقف تزامن عام (429 مسجَّل) وسقوف حجم/مهلة/أنفاق | متصفح كامل (C3/C4) — لا Chromium في هذا الصندوق |

**الخلاصة الصادقة:** ما بُني هو **قارئ ويب محكوم بإسناد**، لا «وكيل بحث وفهم». الفجوة الأكبر ليست في الشبكة، بل في **عقد الادعاء**: اليوم الملخّص نص حر يحمل روابط، ولا شيء يمنع سطرًا مستنتَجًا من الظهور كأنه مقتبس.

## 3. نقد بناء (بما فيه نقد ما بنيتُه أنا)

1. **الملخّص ادعاء تنفيذي بلا عقد.** أسوأ من غياب الميزة: ميزة تُوهم بالإسناد. سطر «نما 12% — المصدر: X» يمكن أن يكون **استنتاجًا** لم يقله المصدر. → **S1** عقد ادعاء صارم قبل أي بحث.
2. **مصدرا حقيقة للتدقيق.** الوسيط يكتب `egress_request`، والأداة تكتب `web_source`. إن انهارت العملية بين الاثنين، تظهر رحلة بلا مصدر مسجَّل. → توحيد: صف واحد مركّب (`correlationId` مشترك) أو تسلسل ملزم + اختبار انقطاع.
3. **البصمة على النص المنقّى لا على الصفحة.** قرار صحيح للمخطِّط، لكنه يجعل مقارنة «هل تغيّرت الصفحة؟» مستحيلة. → بصمتان: `rawSha256` (للمقارنة) و`readSha256` (لما رآه المخطط).
4. **المنقّي يغيّر النص.** `scanForInjection` يطبّع (تاء مربوطة/تشكيل)، فيتغيّر الاقتباس الحرفي. → عند S1، الاقتباس الحرفي يُتحقق ضد **النص الأصلي** لا المنقّى.
5. **المخطط يفهم بالنمط.** `WEB_INTENT_HINTS` قائمة كلمات: هشّة بالعربية والإنجليزية، وقد تُخطئ. مقبول كحل مؤقت — لكن يجب أن يُقاس معدل الخطأ بعيّنة أوامر، وإلا فهو انطباع.
6. **`maxConnections` عالمي لا لكل تشغيل.** تشغيل ثقيل يمكنه استهلاك السقف كله. → حد لكل تشغيل + لكل مضيف (S3).
7. **ميزانيات في الذاكرة.** إعادة تشغيل = صفر. → تسجيل الاستهلاك في المخزن (S3) ليصبح الحد صارمًا عبر العملية.
8. **`web.fetch` قادر — بحكم القائمة — على لمس عناوين داخلية.** هذه ليست ثغرة اليوم (لا شيء مُفعَّل)، لكنها **قنبلة موقوتة** عند أول تفعيل حقيقي. → منع النطاقات الخاصة بعد الحل (S3) **قبل** أي تفعيل.
9. **لا حد لعدد الوجهات المختلفة في التشغيل** (٣ روابط، لكن كلها قد تشير إلى مضيفين مختلفين). → سقف مضيفين لكل تشغيل.
10. **الاختبارات تقيس السلوك لا الجودة.** ٦/٦ تعني «يفعل ما وصفناه»، لا «ملخّصه مفيد». → لا ادعاء جودة قبل S6 + تقييم بعيّنة بشرية.

## 4. خطة الإغلاق — شرائح مرتبة

### S1 — عقد الادعاء والإسناد (بلا قرار مالك) ← **أبدأ بها**
- `src/agent/claims.js`: `claim { text, sourceUrl, kind: 'quote'|'inference', basis[], digest }`.
- رفض: ادعاء بلا مصدر · اقتباس غير حرفي · استنتاج بلا أساس.
- صف أدلة جديد `claim_attribution` (بصمة الادعاء + مرجعه).
- **معايير القبول:** ‏CL-01 ادعاء بلا مصدر لا يُسلَّم · CL-02 اقتباس مُحرَّف يُرفض · CL-03 استنتاج بلا أساس يُرفض · CL-04 استنتاج مبني على اقتباسات يُعلَّم · CL-05 السلسلة متحققة بعد التسليم.

### S2 — كشف تعارض المصادر (بلا قرار) ← يتبع S1
- `src/agent/conflicts.js`: أرقام/نسب/تواريخ منسوبة لكل مصدر؛ تعارض صريح بقيمتيه ومصدرَيه، **بلا اختيار صامت**.
- **معايير القبول:** ‏CF-01 تعارض مكتشف ومسمّى · CF-02 توافق ≠ تعارض · CF-03 قيمة يتيمة ليست تعارضًا · CF-04 التعارض تحذير في التسليم لا حذف.

### S3 — تقوية الجلب (بلا قرار، لكن `robots` سياسة)
تغطي G7–G10، G12، G13، G15:
- كشف ترميز (`charset` + BOM) قبل التحويل · سقف بعد فك الضغط · رفض `https→http` · **فحص IP بعد الحل** ومنع RFC1918/loopback/link-local · `robots.txt` (قرار: احترام افتراضيًا) · كاش مشروط (ETag/Last-Modified) · سقوف لكل مضيف وللعملية في المخزن · دعم وسيط أعلى اختياري.
- **معايير القبول:** ‏FH-01 صفحة `windows-1256` تُقرأ صحيحة · FH-02 قنبلة gzip تُرفض بكود مسمّى · FH-03 هبوط المخطط يُرفض · FH-04 مضيف مسموح يُحلّ إلى `10.0.0.5` → **منع** · FH-05 `robots` يمنع مسارًا ممنوعًا · FH-06 الطلب الثاني يستخدم كاش · FH-07 حد لكل مضيف.

### S4 — مقبض البحث + رفض صريح (يحتاج قرار مزوّد)
- `src/agent/web-search.js`: واجهة `search({ query, limit })` + مزوّد وهمي للاختبار + **رفض مسمّى** بلا مزوّد.
- **معايير القبول:** ‏WS-01 بلا مزوّد = `web_search_provider_required`، صفر طلبات · WS-02 نتائج مربوطة بحد (≤5) وبلا HTML · WS-03 كل نتيجة تمر بالقائمة قبل أي جلب.
- **قرار مالك:** المزوّد (Brave/Google CSE/Serper) + المفتاح + التكلفة.

### S5 — اختيار المصادر في المخطط (يتبع S4)
- المخطط: استعلام → نتائج → اختيار ≤3 → جلب → S1/S2 → تسليم بإسناد وتعارضات.
- **معايير القبول:** ‏WS-04 سؤال بلا روابط يُنتج مصادر مختارة · WS-05 لا يتجاوز ٣ · WS-06 كل ادعاء مصدره من النتائج لا مخترع.

### S6 — مقبض النموذج للتلخيص الدلالي (يحتاج قرار تشغيل)
- `src/agent/summarizer.js`: واجهة نموذج + سقوط حتمي إلى المقتطفات + رفض ادعاء بلا مصدر حتى لو جاء من النموذج.
- **معايير القبول:** ‏SM-01 بلا نموذج = مقتطفات منسوبة · SM-02 نموذج وهمي يُنتج ادعاءً بلا مصدر → يُرفض · SM-03 الاستنتاج من النموذج يُعلَّم `inference`.
- **قرار مالك:** تشغيل Ollama/Llama (عَتاد، زمن، جودة) + قرار: هل بيانات داخلية تُمرَّر لنموذج خارجي؟ (توصيتي: **لا** — محلي فقط).

### S7 — تفعيل حقيقي في بيئة (يحتاج قرار نشر)
- `proxy` + قائمة مضيف واحد عام (مثال: `https://example.com`) + قياس حقيقي: زمن، حجم، نسبة نجاح، أول كشف حقن حقيقي.
- **معايير القبول:** ‏LV-01 تشغيل حقيقي مسجَّل بالتاريخ · LV-02 `egress_request` مطابق · LV-03 لا خروج لمضيف خارج القائمة.

### S8 — ربط الشبكة الداخلية (يحتاج قرار + تصميم مصادقة) ← تفصيله في §5

## 5. ربط الشبكة الداخلية — ما أوصي به، وما أحذّر منه

### القاعدة الأولى: **لا تُوصَل الشبكة الداخلية عبر `web.fetch`**
`web.fetch` صُمّم لقراءة صفحات عامة بلا أسرار. استخدامه لخدماتك الداخلية يعني:
- مصادقة داخل عنوان URL أو ترويسة لا نملك مكانًا آمنًا لها،
- وفتح مسار يقرأ شبكتك الداخلية بأداة **بلا موافقة** (نوعها `read`).

**البديل الصحيح: `connectors`** (القائم فعلًا: readers للقراءة + `outbox` للكتابة بموافقة وidempotency). أي نظام داخلي = موصل بعقده ومصادقته وسجل تدقيقه.

### تصميم مقترح للربط (D-قرارات)

| البند | التوصية | السبب |
|---|---|---|
| **المسار** | connector داخلي مستقل (transport خاص) لا عبر وسيط الويب | فصل بيانات الملك عن صفحات عامة |
| **المصادقة** | من البيئة/الخزنة، داخل الـconnector فقط، لا تظهر في أدلة ولا في `args` | `web.fetch` لا يحمل أسرارًا بالبناء |
| **العناوين** | قائمة صريحة `http://svc.internal:8080`، **لا** `*.internal` | منع التوسّع الضمني |
| **DNS** | منطقة داخلية + **تثبيت IP**؛ اختلاف الحل = فشل مغلق | يعالج G10 |
| **الكتابة** | عبر outbox + موافقة، بنفس بوابة `google.drive_export_report` | لا أثر خارجي بلا موافقة (DEC-055/058) |
| **البيانات** | تصنيف: داخلي لا يخرج لنموذج خارجي؛ تلخيص محلي فقط | يعالج قرار S6 |
| **التدقيق** | `egress_request` + `web_source` + `claim_attribution` ← SIEM عبر sink مع تنقية | سلسلة واحدة قابلة للتدقيق |
| **الشبكة الفعلية** | إن لزم وسيط الشركة: **وسيط أعلى** اختياري (S3/G15) لا فتح مسار ثانٍ | مسار خروج واحد = سياسة واحدة |

### «تغذية الشبكة الداخلية» بمعنى ثانٍ: تغذية **مكوّنات CeliaOS** ببعضها
هذا أقرب شيء إلى DEC-061 (طبقة المحوّلات). توصيتي **بديل أخف** يوصل المكوّنات بلا إعادة بناء:
1. **`toolDescriptor` موحّد**: `{ name, risk, approval, argsSchema, costHint, readOnly }` لكل أداة — يُستهلك من السجل القائم بدل طبقة محوّلات.
2. **`traceRef = runId#step`** واحد يربط: خطوة المخطط ← تنفيذ الأداة ← صف الدليل ← قرار الوسيط. لا `trace_id` ثانٍ.
3. **مخطط أدلة موحّد**: `kind` + `verdict` + `ref` إلزامي في كل صف (اليوم موزّع على أنواع).
4. النتيجة: كل مكوّن (ويب، بحث، متصفح، موصل) يُغذّي الشبكة الداخلية **بعقد واحد** — بلا محوّلات ولا سطح صلاحيات ثانٍ.

## 7. الترتيب الذي سأنفّذه (بلا انتظار قرارات)

```
S1 (عقد الادعاء) → S2 (التعارض) → S3 (تقوية الجلب + منع العناوين الداخلية)
   ↳ عندها فقط: S4/S5 (بحث) ⟵ D1        S6 (نموذج) ⟵ D2        S7/S8 ⟵ D4/D5
```

**لماذا S3 قبل أي تفعيل حقيقي:** G10 (rebinding إلى عنوان داخلي) وG8 (قنبلة فك الضغط) تعملان **ضدّنا** في أول يوم اتصال حقيقي. إغلاقهما قبل فتح الباب هو نفس منطق «الباب قبل المفتاح» في C1.

**ما لن أفعله:** لن أعتبر 789 اختبارًا محليًا إثباتًا للإنترنت العام، ولن أُطلق بحثًا أو نموذجًا على تخمين، ولن أفتح مسارًا ثانيًا للشبكة الداخلية يوازي `connectors`.
