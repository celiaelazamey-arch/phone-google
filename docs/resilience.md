# حدود العطل والمراقبة

## مسار الطلب

```text
HTTP / MCP / واجهة مستقلة
 ├─ storage         [مهلة 3s، حد 5 عمليات + طابور MySQL محدود]
 ├─ google.gmail    [قاطع مستقل]
 ├─ google.drive    [قاطع مستقل]
 ├─ google.calendar [قاطع مستقل؛ لا إعادة إنشاء تلقائي]
 ├─ google.contacts [قاطع مستقل]
 ├─ google.oauth    [قاطع مستقل]
 ├─ whatsapp        [قاطع مستقل؛ لا إعادة إرسال تلقائي]
 ├─ gemini          [قاطع مستقل]
 └─ ollama → local-policy [بديل قواعد محافظ في auto]
```

`src/resilience.js` يطبّق timeout + AbortSignal + bulkhead + circuit breaker. القاطع يُفتح بعد إخفاقات متتالية، ويقبل محاولة واحدة فقط بعد cooldown (half-open). النجاح يعيده مغلقًا، وفشل المحاولة يعزله مجددًا. النتائج المتأخرة من طلبات أقدم لا تغلق قاطعًا جديدًا. إذا تجاهلت مكتبةٌ الإلغاء، يبقى موضعها محجوزًا حتى تنتهي لمنع تكدس عمل مخفي.

## السلوك عند تعطل مكوّن

| العطل | السلوك الآمن | ما يستمر |
|---|---|---|
| Gemini غير متاح/429/مهلة | `auto` ينتقل إلى Ollama ثم الحارس المحلي. `gemini` الصريح يفشل بوضوح | HTTP، الواجهة، أدوات مستقلة |
| Ollama غير متاح | `auto` يعود لقواعد محلية؛ ليس نموذجًا توليديًا ولا يختلق تنفيذ إجراء | الرد المحلي وبقية الخدمات |
| MySQL غير متاح عند البدء أو أثناء التشغيل | لا استبدال بالذاكرة؛ `/readyz`=503 وعمليات البيانات تفشل مغلقة. نفس الـpool يحاول التعافي لاحقًا | `/health`، `/version`، UI، الرد المحلي |
| Gmail | قاطع Gmail لا يفتح قاطع Drive أو Calendar | الخدمات المستقلة |
| WhatsApp يتأخر بعد طلب إرسال | مهلة و`outcomeUnknown`؛ لا replay | النواة وبقية الخدمات |
| طلب حالة فاشل في الواجهة | آخر قيم ناجحة موسومة قديمة، وسجل الإصدارات مستقل | بقية لوحة النظام |
| SIGTERM/SIGINT | readiness تُصبح غير جاهزة، drain حتى 10s، ثم إغلاق الاتصالات والتخزين | لا قبول نشر ناجح أثناء الإغلاق |

## الإعدادات

راجع `.env.example`:

- `CELIA_SERVICE_TIMEOUT_MS=8000` (50–60000)
- `CELIA_CIRCUIT_FAILURE_THRESHOLD=3` (1–20)
- `CELIA_CIRCUIT_COOLDOWN_MS=30000` (100–300000)
- `CELIA_SERVICE_CONCURRENCY=6` (1–32)
- `CELIA_DISABLE_GOOGLE/WHATSAPP/GEMINI/OLLAMA=true` لمنع الاستدعاء الخارجي لتكامل اختياري؛ تتطلب تغييرات البيئة إعادة تشغيل. تعطيل الإرسال لا يمسح رسائل أو موافقات مخزنة.

لا توجد محاولات إعادة إرسال/إنشاء مواعيد أو تغيير إصدارات غير مصادق عليها عبر واجهة المتصفح. أخطاء الإدخال أو نقص الموافقة أو صلاحيات 4xx ليست أعطال بنية تحتية تفتح القاطع. 408/429 و5xx محسوبة ضمن الأعطال.

## نقاط الفحص

| المسار | الوصول | المعنى |
|---|---|---|
| `/health`, `/healthz` | عام، دون أسرار | liveness سريع بلا اتصال بمزوّد خارجي |
| `/readyz` | عام | النواة لا تُغلق والتخزين متاح؛ 503 عند فشل التخزين |
| `/version` | عام | إصدار التشغيل، عقد المخطط، commit إن وفّرته الصورة |
| `/api/system` | عام | حالات منقحة ومقاييس قواطع داخل هذه العملية؛ فحص DB مجمع ومخزن لـ1s |
| `/api/releases` | عام | سجل **المصدر**؛ ليس ضمانًا أن كل إدخال منشور |
| `/api/system/diagnostics` | Bearer المالك | عدادات وأحداث دائرة محدودة دون رسائل SDK الخام |
| `/system` | عام على MCP | لوحة عربية responsive مع تصدير JSON |

Google/WhatsApp «غير مُهيّأ» لا يعني تعطل النواة. و«بانتظار الاستخدام» لا يعني نجاح فحص اتصال؛ نجاح استدعاء فعلي هو ما يسجّل `lastSuccessAt`. في Pages الحالة تخص المتصفح وليست خادمًا حقيقيًا.

## الخصوصية والأمان

- العرض العام لا يستخدم مفاتيح مزود الذكاء الاصطناعي الخاصة بالمالك. استدعاء خارجي من الخادم يحتاج رمز المالك.
- مفاتيح يُدخلها المستخدم في الاستوديو تبقى في `sessionStorage` ويُستخدم كل منها مع مزوّده فقط. لا تستخدمها في متصفح مشترك؛ XSS يمكن أن يقرأ sessionStorage، لذلك تجنّب سكربتات طرف ثالث واحفظ مفاتيح الإنتاج على الخادم.
- متصفح المعاينة لا يتصل بـlocalhost لخادم آخر؛ Ollama يُستدعى عبر MCP على نفس الأصل، وعنوانه يُضبط على الخادم فقط. لا حاجة إلى `OLLAMA_ORIGINS="*"`.
- لا تبديل تلقائي إلى مزود سحابي جديد عند الفشل. البدائل على الخادم معالجة محلية فقط.
- موافقة WhatsApp + موافقة AI المنفصلة + نافذة 24h ما زالت مطلوبة. سياسة الرد ليست ضمانًا رياضيًا لسلوك نموذج توليدي؛ راجع المخرجات الحساسة بشريًا.
- لا تسجل المفاتيح أو بيانات العميل أو رسائل SDK الخام. لا تكرر عملية كتابة عند مهلة؛ قد تكون نجحت لدى المزوّد قبل انقطاع الرد. افحص حالتها أولًا.

## حدود العزل والاختبارات

هذا عزل **منطقي داخل عملية Node واحدة**، لا microservices موزعة ولا تحمل كامل لانهيار النواة/OOM/انقطاع الجهاز/الشبكة. `restart: unless-stopped` يستعيد الحاوية بعد crash، لكنه ليس ضمان توافر. للإنتاج الحرج أضف عمليات مستقلة، replicas، load balancer، مراقبة خارجية، نسخ بيانات احتياطية وعمليات failover مختبرة.

```bash
npm ci
npm run check
npm run release:check
npm test
npm run test:resilience
npm audit --omit=dev
npx playwright install --with-deps chromium
npm run test:browser
```

الاختبارات المحلية تغطي القواطع والمهل والتزامن والتعافي وغياب تسرب الأسرار، فشل التخزين مع استمرار النواة، وفشل المرشّح/التفعيل/الفحص/حفظ الحالة/الرجوع نفسه. اختبارات المتصفح تغطي الهاتف/الحاسوب وPages تحت مسار المستودع وفشل لوحة مستقلة وفحوص axe WCAG 2 AA الآلية (وليست شهادة إتاحة كاملة). CI يختبر Node 22 و24، ويضيف smoke test لحاوية Node 24. فحوص Gemini الحية منفصلة واختيارية على `main`، ولا تُستخدم مفاتيح الإنتاج في pull requests.
