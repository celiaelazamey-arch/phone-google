# وسيط الخروج (egress proxy) — M-C / C1

> **الحالة:** **C1-a** منفَّذة (الوسيط + سياسة per-run + التدقيق). **C1-b + C2-a** منفَّذتان على فرع `arena/df8cbebc-phone-google` (ربط الإقلاع + `web.fetch` + أدلة لكل مصدر). **C2-b** (`web.search`) **لم تُنفَّذ**: تحتاج قرار مزوّد من المالك.
> **القرارات:** [DEC-059](continuity/DECISIONS.md) (الوسيط) · DEC-060 (الشبكة في العزل تبقى `deny` دائمًا، والويب على المضيف) · DEC-061 (مطابقة مخطط 2026) · DEC-062 (الحلقة: جلب ولخّص باسناد URL لكل سطر).
> **الاختبارات:** `test/agent-egress-proxy.test.js` (EP-01..EP-14) · `test/agent-web-access.test.js` (WB-01..WB-14، WB-03b) · `test/agent-web-run.test.js` (WR-01..WR-06، الحلقة) · البوابة `npm run eval:web` (WEB-01..WEB-11).

## 1. لماذا هذا المكوّن هو الأخطر في الخطة

حتى اليوم، سياسة العزل في `src/agent/sandbox-policy.js` ترفض أي شبكة **بالكود**:

```js
if (network.mode !== 'deny') throw new Error('sandbox_network_must_default_deny');
if (!Array.isArray(network.allowlist) || network.allowlist.length !== 0) {
  throw new Error('sandbox_egress_allowlist_backend_unavailable');
}
```

هذا يعني أن أول سطر يفتح الشبكة هو أيضًا أول سطر يفتح ثغرة. لذلك بُني **الباب قبل المفتاح**: لا وجود لأي فتح في العزل، والوسيط وحده هو ما يمكن أن يفتح لاحقًا — وهو مبنيّ ومختبَر أولًا.

## 2. نموذج التهديد وترتيب الإنفاذ

| القاعدة | كيف تُنفَّذ في الكود | كيف تُقاس |
|---|---|---|
| **لا منحة = لا حزمة** | `resolveGrant` يرفض 407 قبل تحليل الهدف أصلًا | EP-02، EP-10 |
| **القرار قبل DNS** | مطابقة نصية للـhost ضد قائمة التشغيل؛ المحجوب لا يصل `http.request`/`net.connect` | EP-04 (اسم لا يُحل + IP غير مدرج = 403 فوري، وصفر اتصال بالخادم الشرير) |
| **قائمة لكل تشغيل** | `issueGrant({ runId, allowlist })` → رمز معتم 64-hex؛ لا قائمة مشتركة بين التشغيلات | EP-02، EP-10 |
| **حدود واضحة** | `host` أو `host:port` أو `*.suffix` — والبدل لا يطابق الأصل ولا `evilexample.com` | EP-01 |
| **لا محارف ملتبسة** | IDN يُرفض بدل تطبيعه (لا `xn--` ضمني، لا تشابه بصري) | EP-01 |
| **كل قرار في الأدلة** | `onEvent` لكل قرار: سماح أو منع، مع الدومين والمنفذ والمساري والحجم والحالة والمدة | EP-03، EP-09 |
| **لا أسرار في السجل** | لا ترويسات ولا query strings ولا رمز منحة | EP-08 |
| **سقوف تقطع** | تجاوز حجم الطلب/الرد أو المهلة أو سقف الأنفاق يقطع الدفق ويُسجَّل `blocked` | EP-06، EP-07 |
| **الافتراضي مغلق** | `createEgressAllowlist({ hosts: [] })` = منع كل شيء؛ `*` مرفوض بالبناء | EP-01، EP-11 |

## 3. السطح

```js
import { createEgressProxy, createEgressAllowlist, createEvidenceEgressSink } from './src/agent/egress-proxy.js';

const proxy = createEgressProxy({ onEvent: createEvidenceEgressSink({ store }) });
const { url } = await proxy.listen({ port: 0 });          // 127.0.0.1 فقط
const grant = proxy.issueGrant({ runId, allowlist: ['api.example.com:443', '*.cdn.example.com'], ttlMs: 300_000 });
// داخل التشغيل: HTTPS_PROXY=url + Proxy-Authorization: Bearer <grant.token>
```

- **HTTP:** صيغة absolute-form (`GET http://host/path`) مع تمرير الترويسات السليمة وحذف hop-by-hop.
- **HTTPS:** `CONNECT host:443` وحده؛ لا فك تشفير ولا شهادة جذرية مزروعة.
- `revokeRun(runId)` / `revokeGrant(token)` / `activeGrants()` / `events()` / `stats()`.
- السقوف الافتراضية: 1MiB طلب، 8MiB رد، 15s مهلة، 8 أنفاق لكل منحة — قابلة للضبط عند الإنشاء فقط.

## 4. ما لم يُنفَّذ (بصراحة)

1. **`web.search` غير موجودة عمدًا (C2-b).** تحتاج مزوّدًا (Brave/Google CSE/Serper بمفتاح وتكلفة) أو كشط HTML هشًّا مشكوكًا في شروطه — قرار مالك أولًا، على غرار `GOV-001`. لا يُبنى على تخمين.
2. **العزل ما زال `deny` حرفيًا.** EP-11 يحرس ذلك: `network.allowlist` ما زال مرفوضًا في `sandbox-policy.js`.
3. **الربط مشروط بالكامل.** في `createAgentHost` لا يُنشأ وسيط ولا أداة إلا بـ`CELIA_AGENT_EGRESS=proxy` **وقائمة صريحة**؛ الافتراضي `off` يعني صفر مقابس وصفر أدوات (WB-12).
4. **لا قياس حي على إنترنت حقيقي.** كل الاختبارات على مقابس محلية (خادم وجهة وهمي + خادم «شرير» يجب ألا يُلمس). أي اتصال خارجي قرار نشر منفصل.

## 5. القرار المعماري المقترح لـC1-b (انحراف مُعلن عن نص الخطة)

نص الخطة يقول «عندها فقط تُفتح `network.allowlist`». الأنفع والأقوى — وقد يكون ما نفعله فعلًا — أن **تبقى الشبكة في العزل `deny` إلى الأبد**، وأن تُنفَّذ أدوات الويب **على المضيف عبر الوسيط** (كما تعمل بقية الأدوات)، فيصبح العزل بلا شبكة أصلًا وليس «بشبكة مسموحة».

مزايا ذلك:
- لا حاجة لبناء veth/slirp داخل namespace المهمة ولا لصلاحيات `CAP_NET_ADMIN` وقت التشغيل.
- كل طلب يمر بمنحة تشغيل واحدة وقائمة واحدة وسجل واحد — لا مسار شبكة ثانٍ يُدقَّق بشكل مختلف.
- يقلّل سطح الهجوم: لو انكسر العزل، لا شبكة هناك ليُستغلّ.

العيب الوحيد: جلب الصفحات يتم على المضيف لا داخل العزل، أي أن صفحة خبيثة تُعالَج في عملية المضيف — وهو ما تحكمه C5 (فحص الحقن قبل أن يرى المخطط أي نص) والسقوف والحجم.

**حُسم القرار:** DEC-060 — العزل يبقى `deny` دائمًا، والويب على المضيف عبر الوسيط. لم يُفتح `network.allowlist`، ولم تُضف أي صلاحية حاوية.

## 6. C1-b — الربط بالإقلاع

```
CELIA_AGENT_EGRESS=off|proxy          # off افتراضيًا؛ أي قيمة أخرى تُفشل الإقلاع
CELIA_AGENT_EGRESS_ALLOWLIST=a.com,*.cdn.example.com:443
# تُقبل أيضًا صيغة المخطط: https://api.example.com → api.example.com:443 (منفذ مثبَّت)
CELIA_AGENT_EGRESS_MAX_CONNECTIONS=16 # سقف الطلبات المتزامنة في الوسيط كله
CELIA_AGENT_WEB_MAX_FETCHES=6         # لكل تشغيل
CELIA_AGENT_WEB_MAX_CHARS=80000       # لكل تشغيل
```

- `readAgentEgress(env)` وحدها تقرأ البيئة: `proxy` بلا قائمة → `agent_egress_allowlist_required`، وقائمة `*` → `agent_egress_allowlist_invalid`، وقيمة غير معروفة → `agent_egress_misconfigured`. لا «افتراضي متساهل» في أي فرع.
- الوسيط يستمع على `127.0.0.1:0` فقط؛ عنوانه لا يُنشر خارج العملية.
- `/api/agent/egress` (خلف تفويض المالك): `{ mode, hosts, url, stats }` — أعداد وقرارات، **ولا رمز منحة ولا ترويسة** (WB-13).
- **دورة حياة المنحة:** `createWebAccess.fetch` يصدر منحة واحدة بصلاحية 30s ثم `revokeGrant` في `finally` — نجاحًا أو فشلًا أو إلغاءً. لذلك `activeGrants()` فاضية بين الخطوات (WB-03، WB-10).

## 7. C2-a — `web.fetch`

```json
{
  "version": "agent-web-fetch-v1", "url": "...", "finalUrl": "...", "status": 200,
  "contentType": "text/html", "title": "...", "text": "...", "chars": 2140, "bytes": 9120,
  "truncated": false, "hops": [{"url": "...", "status": 200}], "sha256": "…",
  "fetchedAt": "…", "injection": { "tainted": true, "score": 12, "ruleIds": ["override_en"] }
}
```

- **كل رحلة تُعاد فحصها بالقائمة** (حتى 3 redirects) قبل أي اتصال؛ الهدف الخارجي لا يُلمس (WB-06، WEB-04).
- **الحقن يُنقّى قبل المخطِّط:** نفس `scanForInjection` المستخدم في خط القضايا. المخطِّط يرى النص المنقّى + معرّفات القواعد، و**البصمة تُحسب على المنقّى** — فالدليل يشهد على ما قُرئ فعلًا لا على ما وصل. المنقّي يطبّع أيضًا (تاء مربوطة/ياء/تشكيل)، فالنص المنقّى ليس بايتًا-ببايت الأصل.
- **الأدلة:** صف `web_source` لكل محاولة — `PASS` مع بصمة، أو `BLOCK` مع الكود وبلا بصمة. النص لا يُخزَّن أبدًا؛ الهاش في الصف يساوي حرفيًا كائن الميتاداتا (WB-14 يثبت ذلك بمقارنة `hashOf`).
- **السقوف:** 2MiB للرد، 20s، 20 000 حرف للصفحة، 6 جلب/80 000 حرف للتشغيل — الكل مُتحقَّق في الإنشاء (`web_limit_invalid:<key>`).

**ثلاثة مصادر لكل ادعاء** مُثبتة كصف أدلة في WEB-09: ثلاثة جلب → ثلاثة صفوف `PASS` بثلاثة URLs وثلاث بصمات مطابقة لما رآه المخطِّط.

## 8. ما تقيسه البوابة الآن

`npm run eval:web` → `WEB-ACCESS: PASS — 11/11` (`reports/web-access.json`، حتمي بلا طوابع زمنية). يغطي: مصدرًا كاملًا بالبصمة، رفض المضيف بلا اتصال، redirect داخلي/خارجي، سقف الحلقة، نوع المحتوى، الحجم، تنقية الحقن، ثلاثة مصادر، ميزانية كل تشغيل + سحب المنحة، وتسجيل كل قرار خروج.

**ما لا تقيسه:** إنترنتًا حقيقيًا. كل المشاهد على `127.0.0.1`. أي اتصال فعلي بالعالم قرار نشر مستقل بتاريخه.

## 9. مطابقة مخطط 2026 (`CELIA_AGENT_EGRESS`) بالكود — ادعاء بادعاء

المخطط الهندسي المرفق يصف طبقة «مضيف + محوّل موحّد». هذا جدول يقابل كل عنصر بما هو **موجود فعلًا** وبما **ليس موجودًا**، حتى لا يُقرأ المخطط كأنه وصف للحالة:

| عنصر المخطط | الحالة هنا |
|---|---|
| `mode: 'off'` افتراضيًا، `proxy` عند الطلب | ✅ `readAgentEgress(env)`؛ أي قيمة ثالثة تُفشل إنشاء المضيف |
| `allow: ['https://api.example.com', 'https://*.trusted.com']` | ✅ **مقبولة الآن**: `normalizeEgressEntry` تترجمها إلى `api.example.com:443` و`*.trusted.com:443` — أي **أضيق** لا أوسع (المخطط يثبّت المنفذ) |
| `deny: ['*']` | ✅ سلوكًا: كل ما ليس في `allow` محجوب؛ ويعود صريحًا في `/api/agent/egress` |
| `proxy: null` (لا وسيط أعلى) | ✅ لا توجيه لوسيط أعلى بالبناء، ويُعلن `upstreamProxy: null` في الرد |
| `maxConnections: 3` | ✅ **صار سقفًا حقيقيًا**: افتراضي 16، `CELIA_AGENT_EGRESS_MAX_CONNECTIONS`، وتجاوزه = 429 `egress_connection_limit` **مسجَّل** (EP-14) |
| «فحص الإعدادات وتأكيد صحة القائمة» عند الإنشاء | ✅ `createEgressAllowlist` ترفض `*` والمسارات والاعتماديات؛ والإعداد الخاطئ يُفشل الإقلاع لا يُهمَل |
| «منحة لكل عملية جلب» | ✅ منحة لكل `web.fetch` تُسحب في `finally` (WB-03/WB-03b) |
| «تسجيل الأدلة» بنوع مستقل | ✅ `web_source` لكل محاولة + `egress_request` لكل قرار وسيط |
| «التحقق النهائي / result-verifier» | ✅ بأسماء أخرى: `evidence.js` (سلسلة hash) و`verifier.js` و`harness.js` |
| **`unified-converter.js` + `computer/browser/tool/mcp/data/service-converter.js`** | ❌ **غير موجودة إطلاقًا** في هذا المستودع (لا ملف واحد باسم `converter`). البنية الفعلية: `runtime.js` → `tools.js` (سجل أدوات مع سياسة لكل أداة) → تنفيذ الأداة |
| **`agent-runtime.js`** | ❌ الاسم هنا `runtime.js` (الملف المقصود غير موجود) |
| **عقد JSON موحّد للطلب/الاستجابة مع `trace_id` و`permissions`** | ❌ لا يوجد عقد موحّد. لكل أداة تعريفها ومخطط مدخلاتها، والخيط هو `runId`، والدليل هو `sha256` + سلسلة الأدلة |
| **`checkPermissions()` كفحص مركزي قبل المحوّل** | ⚠️ موجود **بمعناه** لا بشكلِه: `tool-policy.js` (نوع الأداة وخطرها) + `web.fetch` بوصفها `read` + قائمة التشغيل + سقوف الميزانية |
| **`createHost({ egress: CELIA_AGENT_EGRESS })` ثابتًا من `config.js`** | ⚠️ وجوديًا: لا `config.js` ولا معامل `egress` مُحقَن؛ `createAgentHost` يقرأ البيئة ويبني الوسيط بنفسه عند `proxy` |

### ما أوصي به في شأن الجزء غير الموجود

طبقة المحوّلات ليست «توصيلًا» بل **إعادة بناء**: لا شيء منها في المستودع، وكل ما تعِد به (توجيه حسب القدرة، عقد موحّد، فحص صلاحيات مركزي) موجود اليوم موزّعًا على `tools.js` + `runtime.js` + `evidence.js` + `verifier.js`. إضافتها الآن تعني:
1. إعادة تسمية/تغليف كود عامل ومختبَر (مخاطرة انحدار بلا قدرة جديدة)،
2. سطحًا ثانيًا للتحقق من الصلاحيات يمكن أن يخالف `tool-policy` (وهذا أسوأ من غيابه)،
3. `trace_id` جديدًا بجانب `runId` بلا حسم أيّهما المرجع في الأدلة.

**المقترح:** إن كان الهدف توحيد MCP/الأدوات، فالشريحة الصحيحة هي **عقد أدوات موحّد + `trace_id` مشتق من `runId`** فوق السجل القائم — لا استبداله. وإن كان الهدف فقط «شكل الإعداد» في المخطط، فقد صار مطابقًا الآن (الصيغة، `deny`, `proxy`, `maxConnections`). القرار في DEC-061.

## 10. الحلقة: كيف تُستدعى الأداة فعلًا (C2-a/loop — DEC-062)

الأداة وحدها لا تُثبت قدرة. هذه هي الحلقة الكاملة كما تُقاس في `test/agent-web-run.test.js`:

```
رسالة المالك (فيها روابط)
  → المخطط الحتمي: يستخرج الروابط (منقّاة، بلا تكرار، ≤3)
  → web.fetch واحدًا واحدًا عبر وسيط C1 (منحة لكل جلب)
  → صف web_source لكل محاولة + صف egress_request لكل قرار
  → تسليم: كل سطر = مقتطف من النص المنقّى + «المصدر: <URL> · بصمة <12>»
```

| السلوك | القاعدة | القياس |
|---|---|---|
| إسناد لكل ادعاء | سطر بلا رابط أو بلا بصمة لا يُسلَّم | WR-01 (3 أسطر لـ3 مصادر) |
| بلا تفعيل | رفض صريح يسمّي `CELIA_AGENT_EGRESS=off`، صفر أدوات/أدلة/اتصال | WR-02 |
| حقن | `تنبيه` + القاعدة التي أطلقت، بلا صدى للحمولة، وقدرة بلا زيادة | WR-03 |
| ميزانية | توقف بكود مسمّى، ومنع تقديم ملخّص ناقص كأنه كامل | WR-04 |
| قائمة | مضيف خارج القائمة: فشل بلا اتصال، وصف `BLOCK` | WR-05 |
| نية كتابة | رابط داخل طلب تصدير/إرسال لا يُشغّل جلبًا | WR-06 |

**حدود هذه الحلقة بصراحة:** الملخّص **مقتطفات منسوبة**، لا تلخيصًا دلاليًا بنموذج. الجلب متسلسل عمدًا ليبقى ترتيب الأدلة حتميًا. ولا بحث (`web.search`) حتى يقرّر المالك مزوّدًا.
