# صفحة «وكيل CeliaOS يستخدم الكمبيوتر» — عرض توضيحي في الموقع

**الصفحة:** `/computer.html` في النسخة المبنية (`public/computer.html` + `public/computer.css`).

## الحالة أولًا — ما هذه الصفحة وما ليست

هذه **صفحة شرح بصري** لمعمارية «الوكيل يستخدم الكمبيوتر»، وليست واجهة لمحرك مُشغَّل. الوضع الفعلي في المستودع:

| الادعاء الشائع | الواقع في هذا المستودع |
|---|---|
| «الوكيل يتصفح وينقر وينفّذ أوامر طرفية» | **غير مُفعَّل.** Backend العزل المحلي `AGENT-003` موجود ومختبر، لكنه غير موصول بـComputer Use؛ التنفيذ خارج الصندوق مرفوض صراحةً |
| «تتبّع تنفيذ حي» | الرسم **ثابت**؛ لا يقرأ من خادم ولا من قياس |
| «5/5 خطوات · 100% · 0 مفاتيح» | **أرقام توضيحية** لشكل اللوحة، لا نتيجة تشغيل |
| «المتصفح حقيقي» | صحيح كـ*هدف تصميمي*، وليس كقدرة مُوصَّلة الآن |

لذلك تبدأ الصفحة بلوحة تحذير صريحة («عرض توضيحي · غير مُفعَّل · `AGENT-003`») قبل أي رسم، ويُعلَّم كل مؤشر بكلمة
**توضيحي**، ويُسمّى السجل «عرض ثابت» بدل شارة «الوكيل نشط» الكاذبة على صفحة ساكنة. هذه الخيارات ليست ذوقًا: يثبّتها
`test/computer-page.test.js`.

ما هو **حقيقي ومتحقَّق** في النظام تجده في [مركز النظام](../public/system.html) وصفحة الوكيل: خادم MCP وأدواته،
جسر Copilot المحكوم (`docs/copilot-mcp/README.md`)، الوكيل المحكوم بالموافقات والـoutbox، وحوكمة تصنيف المشكلات
بسجل تدقيق مسلسل (`docs/issue-triage.md`).

## ما تعرضه الصفحة

1. **الرحلة:** المستخدم → الوكيل → أدوات الكمبيوتر → خطوات التنفيذ → النتيجة مع تحقق مستقل.
2. **المعمارية:** GitHub ⇄ CeliaOS MCP (أدوات محدودة، قراءة فقط، قائمة بيضاء) ⇄ CeliaOS Agent ⇄ جهاز الكمبيوتر.
3. **تتبّع التنفيذ:** ست خطوات مكتملة وخطوة واحدة **محظورة بالسياسة** («تعديل الكود خارج النطاق») — لإظهار أن
   الحظر جزء من التصميم لا استثناء.
4. **الأمان والقيود:** عزل، منع أنظمة حساسة، قائمة شبكة مسموحة، لا مفاتيح، سجل كامل — وبالمقابل ما هو محظور.
5. **المبادئ:** الخصوصية، الأمان، الشفافية، المسؤولية، تطوير مستمر.

## الالتزامات التقنية المفروضة بالاختبارات

- **صفر طلبات خارجية:** لا Google Fonts ولا CDN؛ الخطوط محلية (`public/fonts.css`)، فالصفحة تعمل بلا شبكة خارجية
  ولا ترسل أثرًا لطرف ثالث. الاختبار يفشل عند أي `href`/`src` خارجي أو `url(http…)` في CSS.
- **تقليل الحركة محترم بالكامل:** العنوان المتدرج، النبض، وميض الأسهم، وظهور الصفوف — كلها تتوقف عند
  `prefers-reduced-motion: reduce`، والاختبار يتحقق من وجود الحركات **ومن** قمعها.
- **بنية وصول:** `lang="ar" dir="rtl"`، رابط تجاوز، `h1` واحد، `aria-current` للصفحة الحالية، وكل أيقونة SVG
  `aria-hidden`، و`forced-colors` مدعوم.
- **روابط لا تموت:** كل رابط داخلي في الصفحة يجب أن يُحلّ إلى صفحة مبنية فعلًا؛ الاختبار يفتح الملفات ويتأكد.
- **الوصول للصفحة:** من الاستوديو (`index.html`) ومن صفحة مركز النظام (`system.html`).

## البناء والمعاينة

```sh
npm run build:pages     # ينسخ public/ إلى dist/ ويضيف الطبقة الثابتة
npm run preview:pages   # يخدم dist/ محليًا
```

الصفحة تُنشر تلقائيًا مع بقية الموقع على GitHub Pages (بلا بطاقة) عند دمج الفرع في `main`؛
`deploy-render.yml` لا علاقة له بها.

## الحدود — وما يلزم قبل أن تصبح حقيقية

- لا أتمتة متصفح ولا طرفية في هذه الشيفرة؛ الصفحة وصف معماري.
- تحويلها إلى قدرة فعلية يتطلب ربطًا مستقلًا بـComputer Use بعد مراجعة `AGENT-003`: عزل لكل مهمة، شبكة على قائمة سماح مُنفّذة خارج الوكيل، حدود CPU/ذاكرة/زمن،
  مخزن مخرجات برابط منتهٍ، وسياسة موافقات — وهي **قرار مالك** لا افتراضًا تقنيًا. وجود Backend المحلي وحده لا يفتح النقر أو الطرفية.
- الأرقام ستبقى توضيحية حتى تُربط بمصدر قياس حقيقي؛ وحينها يُستبدل الوسم «توضيحي» بدليل run، لا العكس.
