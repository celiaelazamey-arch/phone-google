# مسار النشر — «انشر» من داخل المنظومة (PUB-001 / DEC-092)

## الغاية

أن تقول المنظومة «انشر» فتفعل ما تفعله لوحة GitHub ولوحة الاستضافة: تتحقق من التغيير والصلاحيات والفحوص، ثم تنشر، وتُظهر النتيجة والرابط، وتحفظ طريقًا للرجوع. والشرط الذي لا يُساوم عليه: **لا تتجاوز توقيعات الإيداعات ولا المراجعات المطلوبة ولا قواعد الحماية** — لأن تجاوزها يعني أن «انشر» صارت ثغرة، لا اختصارًا.

## الحالة اليوم — مقيسة لا موعودة

`npm run publish:status` يطبع الحكم بالأسباب:

```
✕ الحكم: blocked — 6 مانع، 5/12 قاعدة مستوفاة
الطلب: production · 0.2.1 · b6834a9 · بصمة pub:f0b77f04b9e7dec0
  ✕ لقطة الفحوص موجودة — no checks snapshot was supplied
  ✕ قواعد الحماية مقروءة — the protection rules were not read…
  ✕ شجرة العمل نظيفة — worktree clean = false
  ✕ موافقة صريحة مربوطة ببصمة الطلب — no approval for pub:f0b77f04b9e7dec0
  ✕ رقم الإصدار غير منشور ولا مجمّد — the release state was not read…
  ! صلاحية النشر موصولة في المنصة — grant infra.publish.execute wired = false
```

هذا هو السلوك الصحيح: البوابة **لا تفترض الخير**. ما لا تقرأه تعتبره مجهولًا، والمجهول ليس «مسموحًا».

## ما يفعله المسار وما لا يفعله

| الخطوة | الحالة |
|---|---|
| جمع الحقائق المحلية (فرع، مدى، شجرة، توقيعات، إصدار) | يعمل |
| قراءة الفحوص وقواعد الحماية والموافقات والإصدارات المنشورة | **من لقطة يقدمها من يملك القراءة**؛ البوابة لا تملك رمزًا |
| القرار (`ready` / `needs_owner` / `blocked`) بالسبب والمُصلح | يعمل، ومغطّى بـ16 اختبارًا |
| الموافقة المربوطة ببصمة الطلب | يعمل |
| سجل النشر كسلسلة هاش | يعمل، ويُفحص في CI |
| التراجع إلى آخر نشر مختلف | يعمل من السجل |
| **التنفيذ نفسه (دمج/نشر)** | **لا يفعله الوكيل**: الصلاحية غير موصولة، والدمج محجوب بتوقيعات غير موقّعة، وتشغيل سير العمل ممنوع على رمز الجلسة (٤٠٣) |

## القواعد الاثنتا عشرة

`evidence_present` · `protection_known` · `worktree_clean` · `branch_ahead` · `branch_current` · `required_checks` · `signatures` · `review_requirements` · `approval_bound` · `version_fresh` · `capability_wired` · `ledger_intact`

ثلاث منها تستحق التوضيح:

- **`required_checks`:** الفحص المتخطّى ليس ناجحًا. إن كان مطلوبًا فهو مانع.
- **`signatures`:** إذا اشترطت الحماية توقيعًا، فإيداع غير موقّع يمنع النشر، والبوابة لا توقّع ولا تتجاوز. الحل: المالك يدمج بإيداع موقّع، أو يُعاد الدفع بإيداعات موقّعة.
- **`approval_bound`:** الموافقة تُربط ببصمة `pub:` مشتقة من القناة والإصدار والإيداع والملفات. تغييرُ أي حقل بعد الموافقة يُبطلها، فلا تُعتمد موافقة على غير ما نُشر.

## الموافقة والسجل والرجوع

- **الموافقة:** `publishRequest()` ينتج `{ channel, version, commit, artifacts, fingerprint }`، والموافقة تحمل البصمة نفسها. رفضٌ لبصمة يمنع، وموافقةٌ لبصمة أخرى لا تُغني.
- **السجل:** `docs/deployments/ledger.json` سلسلة هاش (`prevHash` + `entryHash`)، و`npm run publish:ledger:verify` يفحصها، وخطوة في CI تمنع تعديل التاريخ.
- **الرجوع:** `rollbackTarget()` يعيد آخر نشر ناجح بإصدار مختلف، أو `null` بصراحة إن لم يوجد سجل.

## ما يلزم لتفعيل التنفيذ — بيد المالك وحده

1. توصيل صلاحية `infra.publish.execute` للممثل الذي ينفّذ (اليوم `wired: false`).
2. مسار تنفيذ مُعتمد: سير عمل ببيئة محمية وموافقة، أو دمج المالك نفسه.
3. إبقاء التوقيع والمراجعة كما هما — لا استثناء للوكيل.

## الحدود

البوابة قرار لا تنفيذ: لا subprocess ولا شبكة ولا رمز. والتدقيق بنيوي: يثبت أن الشروط مستوفاة، لا أن الإصدار سليم بعد نشره. وفحص «الإصدار غير منشور» يحتاج قراءة الإصدارات من GitHub، وهي خارج متناول الجلسة؛ لذلك يظهر مجهولًا حتى تُقدَّم له.
